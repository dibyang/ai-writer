## 吸收和实现

| 可借鉴点 | ai-writer当前情况 | 本轮适配 |
| --- | --- | --- |
| 受保护上下文与预算解释 | 已有授权门禁、相关性召回和超预算拒绝，但错误仅提示加预算 | context超限增加稳定错误码、实际总量、分项、最多十项主要来源和恢复建议；不剪掉约束、不做token精确承诺 |
| 章节工作任务与短程候选 | workflow/decision/plan已有权威状态 | 任务收拢到已有goal/change/beats/forbidden；必要时短推演不同选择的代价，复用decision；不新建另一份状态或固定分支数 |
| 长章逐步展开 | 已有场景承接规范，缺少分段写作后合章流程 | 新增按需chapter-delivery参考：实际前段结尾→续段→合章完整连读→最终单章登记；不把段落当章节，不用固定场数凑篇幅 |
| 分层纲文映射 | 已有章纲及正文哈希、实读报告和意见闭环 | 从最终正文回对有效计划，允许多对多、部分完成与合理临场变化；缺证保持缺证，不自动造对应关系；沿已有source/revision处理变更 |
| 分层记忆与可解释检索 | 已有分卷、增量账本、召回理由/遗漏清单与正文证据 | 继续复用，不引入向量库、第二套记忆目录或自动事实提取；摘要和检索命中仍不能代替原文实读 |
| 版本化审稿和部分覆盖 | 已有范围/哈希绑定及失效、采用/保留/延期/应用/复核 | 继续复用，不搬入47节点DAG或默认总分；未核范围不当文学通过 |

Openwrite的上下文保护提示的是必要输入不能为缩短请求而丢失。本实现独立按现有紧凑JSON字符计量定位占用，保留原授权、哈希和状态校验；没有迁入其Python/Pydantic或模型编排。

novel-creator的若干规范明确标注规划中，相关脚本存在不等于语义门禁已被证实。ai-writer采用场景展开与长线节制的目的，放弃每章固定Beat数、每章新增问题、末尾固定字数内悬念及事件冷却配额；不以关键词命中判断剧情是否完成。

Long-Novel-GPT提供剧情与正文的对应和局部编辑思路；其部分映射实现包含自动补齐/合并。本项目不复制这些实现，以实读引文和缺证声明替代自动填满对应关系。去味仍沿现有按文体流程，不增加高频词即删除、禁止议论或固定删改比例。

## 验证与边界

定向测试覆盖预算精确边界、分项和主要来源明细、失败不落盘/不改状态及授权先行。最终npm test、doctor、独立打包后的回归和当前Codex会话隔离样例的实读记录在N轮报告，数值以实际最终记录为准。没有新跑百章、独立盲读、市场验证或上游项目验收；旧百章结果仍绑定原构建。
