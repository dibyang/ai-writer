# ai-writer 使用手册

受保护续写候选已登记第七章后的小修，见[版本与修订手册](revision-and-sources.md)中的“已登记第七章的小修与重登”。该入口保留原七章版本，以本地候选凭据记录实际修改，不产生主稿提交；普通作品仍沿用正常修订事务。

ai-writer 通过 Codex 阅读、写作和审修；本地工具负责文件、追踪、来源和导出。日常使用可以直接说任务，无需手工编辑追踪 JSON。

首次使用按 [快速入门](quickstart.md)。命令使用者另看 [命令说明](workflow.md)。

工具自有部分采用Apache-2.0，允许依许可使用、修改、商业使用和再分发；第三方参考资料保留各自许可。作品正文及私有资料的权利与工具许可分开，作者不因使用工具而把作品授予Apache-2.0。当前许可与打包要求见[授权与来源](attribution.md)。

## 先选择入口

| 我在哪里 | 正常入口 | 路径怎样填写 |
| --- | --- | --- |
| ai-writer主项目的Codex会话 | 直接说明任务；诊断用`node bin/ai-writer.mjs` | 始终明确目标作品；终端命令加`--project "作品完整路径"` |
| 已初始化的独立作品目录 | 直接说明任务；终端用`node .writer/tool/bin/ai-writer.mjs` | 当前目录含writer.json可省略--project；手册位置以入口--help为准 |
| 尚未初始化的新目录 | 在主项目说“创建新作品到这里” | init使用--path，不对已有作品重新init |

作品路径含空格时在终端加引号；JSON中的作品内引用使用正斜杠相对路径，Codex负责填写。作品根AGENTS/技能/手册可能保留作者定制，更新工具不自动覆盖；不要因旧笔记与新帮助不一致就删除定制。

更新后恢复时，让Codex同时读取随附入口help列出的“当前工具流程技能”。doctor的`skill_root`和`content_root`是本次校验的技能与手册目录，`project_skill_root`指保留的作者技能；修订区的工具资源仍来自父作品安装包。根作者要求继续生效，包内参考补齐当前命令和保护步骤；诊断通过不表示这些文件已经被实际阅读。

## 每轮应该交付什么

结束时让Codex给出五项：作品完整路径与正文位置、已登记范围、实际读稿/审查范围、未登记稿或阻断、当前任务与下一步。多会话未完成修订还应保存本地交接，包含修订ID、独立区路径、原基线、进度、令牌所在文件和未完成项；不要靠聊天回忆或从列表猜令牌。

示例：“这轮写到第3章即停，保存供下个会话恢复的说明，报告哪些已登记、哪些仍待处理，不自动写第4章。”具体长篇阶段及可复制任务见[完整长篇路径](long-form.md)。

## 任务入口

| 我想做什么 | 可以直接告诉 Codex | 主要结果 |
| --- | --- | --- |
| 新建作品 | 创建作品到明确目录，说明文体、题材、篇幅、读者和文风；先规划再写指定范围 | 设定、大纲、正文和追踪 |
| 接着写 | 恢复指定作品状态，先核对待登记正文，再写下一章/场/篇 | 新正文及更新后的追踪 |
| 写长篇 | 启用长篇追踪，建立分卷契约，按近期细纲连续写到指定单元 | 分卷、增量追踪、线索和滚动审查 |
| 带旧稿继续写 | 从指定的自有分章文件建立新作品，先登记旧稿基线，再续写 | 冻结原稿、阅读覆盖、断点进度 |
| 只审查 | 审查指定范围，报告实际原句与阅读代价，先不改正文 | 带范围和哈希的报告 |
| 修改旧章 | 授权润色指定章节，保留哪些内容；处理回退与后续受影响追踪 | 修订稿、原稿备份及重新登记 |
| 去 AI 味 | 按本书声音定点去味，保留事实和剧情，给改前改后对照 | 专项诊断、修订及复核报告 |
| 导出 | 核对未登记稿与审查覆盖，导出当前完整的已登记范围 | 合并草稿、范围与排除清单 |
| 暂停并规划 | 暂停正文，保存本轮只讨论总纲的任务与范围 | next_unit 保留，行动转为规划 |
| 记录作者选择 | 逐项记录已选、候选、未决项，保留我的原话与出处 | 当前决策与历史记录，候选不自动定案 |
| 核对工具 | 比较主项目与随附副本的版本和内容指纹，不更新 | 模块/文档/技能差异与构建状态 |
| 跨章重复复核 | 完整连读指定范围，比较目标、选择、后果与关系变化，保留差异 | 版本绑定功能表、模型比较和原文证据 |
| 登记减负 | 预览待补项，恢复旧changes草案后实读核对 | 自动路径/哈希、保留未变项，不抄全快照 |
| 意见闭环 | 逐条采用、保留或延期，实改后绑定提交，再复核当前稿 | 原意见、真实取舍、实际修改和复核链 |

提供明确作品路径，避免并行作品混用。题材、人物、结论等核心选择以作者要求为准；普通创作细节可授权 Codex 自行处理。

## 小说规划与局部修稿

从简介开始，可让Codex检查“眼前问题能否解决、解决后怎样改变资源/关系/责任并引出下一阶段”。一次性揭晓不一定适合拉成长篇；若后续只是换人重复，应建议缩短、合并或讨论真正的新后果。保留作者方向，不凭这项检查承诺市场表现。全书仍留骨架，近期只细化2–3章，卷契约写本卷实际兑现和下一阶段入口，不新建另一套事实账本。

开篇没抓手、转场生硬、对白像说明书、章末与下章脱节，可直接点明问题。Codex从doctor的`skill_root`按需读`writer-novel/references/scene-connections.md`，先核因果、人物状态与相邻场景，再做最小修复。慢热、温和对白、正常时间词和余韵都可以保留；不自动套固定字数或每章悬念。下一章未写时，只能检查计划是否可接，不能说已经兑现。

示例：“仅审查第4章的对白和第5章开场，保留合作关系与人物声音，指出真实理解损害和应保留内容，不改稿。”授权修订已登记稿时仍走独立区、影响分析、实读重登及意见闭环；技巧参考不代替这些保护。长篇方法位于同一`skill_root`下的`writer-novel/references/story-development.md`，来源见[归属说明](attribution.md)。根作者技能不会随更新覆盖，刷新根手册也不意味着新参考已复制到根技能目录。

长章被压成提要、需要分段写作或计划与成稿有偏差时，按需读取同一skill_root下的`writer-novel/references/chapter-delivery.md`。沿已有beats组织每段进入时的处境、人物行动和实际变化，续段读取实际上段结尾；合章后复读时间、空间、知情与物件承接，再从正文回查goal/change/beats/forbidden。没有原文支持就写缺证；多项计划可以共用一场兑现，临场合理变化也可以保留。分段不是固定场数或强制悬念，中间稿不逐段record，最终只登记真实完整章。

Codex可使用 `assemble --input 合章.json`，按实际顺序、分段路径及SHA256创建新完整章；输入还包含单元号、当前revision和新正文路径。`parts`须引用`分段/`下的`.md`或`.txt`；目标`draft`必须是`正文/`下尚不存在的`.md`或`.txt`，不能输出到`分段/`或覆盖初稿。需要重合章时另取新的正文路径，保留旧稿并实读比较，再让登记输入指向确认后的最终稿；原写前来源仍须有效，不因换路径重取来源哈希。它遵守阶段、范围及修订占用保护，不改状态、不登记。中断后核对完整稿字节；残稿保留后另存，不自动覆盖恢复。形状见 `assemble --help` 和[技术参考](workflow.md)。

合章的`separator`只允许空白。需要分场标记时，先把标记写在实际片段中，再读取该片段的新SHA256；不要把横线或其他正文传成separator，也不要只改输入哈希追认未读的新版本。

全文实读后先确认报告已保存，再预检和登记。可用 `draft_review` 绑定报告与当前正文版本；缺文件、空报告、正文或报告哈希变化都会先于登记写入拒绝。它只核文件版本，阅读与文学结论仍由实际审查负责。`record-preview` 阻断退出1，`record` 输入异常退出2；任何失败都停止依赖步骤，修正后从失败点重试。

同一作品保存context、record-template、record-preview、review-template或replay-input的`--out`草案时，逐条等待命令退出；保存文件也会取得作品写锁，不能因为业务state不变就并发。占用时先核正在运行的命令，不自动删锁、按超时抢锁或改期望revision。已有物件换手的`previous_holder`放在对应ledger条目内，与`custody`同级，值须是当前账本保管人；去向和本章引文仍按实际正文填写。

中途换会话时，将分段路径和版本、已写事件与人物/物件现状、下一未完段、最终章路径、写前模板及当前任务保存为本地交接。分段可放`分段/`等明确目录，别混作下一章；status只列正文库存，不能据此判断所有中间稿是否存在。恢复时实读原片段而非重写开头；若模板来源或修订已变，保留旧输入，核查影响并重读后另取新模板，不能只把旧输入的哈希换成新的。

把完整任务与进程断点分别保存。例如，授权37—39章、这次在38章两段后结束运行：workflow的任务和范围应覆盖37—39章，本地交接记录37已登记、38两段未登记及下一未完行动。不要把“这次运行不写39章”写成永久停写要求，再让下一会话猜是否可以继续。作者真正要求暂停、缩小范围或改变核心选择时，仍以作者要求为准。

恢复半章要同时核对两层事实：登记账本是上一完整章的基线；当前分段是尚未登记的本章进展。后者可能已写完装配、付款等行动，不能因为账本仍停在前一步就重演，也不能提前把残章登记成完整事实。读完原片段再续写，合章后按实际全文补齐增量追踪。若revision、来源、模板和原片段均未变化，继续沿用原写前模板；单纯更换运行进程不需要改workflow或刷新模板。确需调整下一阶段时，在本章登记后、下一章取模板前办理。

旧章完成正式修订后，先以已提交的完整正文恢复。`分段/`和普通交接文件不在修订事务的默认复制、发布范围，旧片段可能仍是修前字节；它们保留作历史，不代表当前稿。让Codex新建绑定当前修订号和正文哈希的交接，列明旧入口已过时。确需从分段继续，再以修后完整章另存一套分段版本，按原顺序合章核对字节一致，并实读确认承接；不覆盖旧分段、不重复登记已提交章节，也不将旧段稿拼回主稿。

确有关键路线难选时，可以短推演各自一两步的选择、代价和后果，复用decision记录作者选择。推演和未选路线不是已发生事实；已选方向不反复重开。纲文回对写在已有审查报告中，记有效计划版本和实际稿哈希；仅审查时不改计划，已登记稿继续走保护修订，不新增一套事实权威或自动评分。

## 如何理解“已完成”

- 文件保存在 `正文/`：文本存在，但不代表追踪已登记。
- 已登记：正文、细纲和已读来源的哈希绑定到当前状态，可用于后续创作。
- 已审查：报告说明实际阅读范围与版本。脚本的 check 只做机械检查。
- 已导出：清单列出的已登记正文已合并。查看 `excluded_drafts`，确认没有遗漏本次需要交付的文件。
- 作者定稿：由作者决定；工具不会把前面几种状态自动升级为定稿或发布。

`status` 的 `draft_inventory.unregistered` 列出未登记的正文候选，可能是新稿、替代版本、回退保留稿或放在正文目录中的归档。不能直接自动删除或合并。让 Codex 实读、核对用途后处理。归档建议放在作品的独立归档目录，保留来源说明。

## 新会话恢复与长篇

长篇正文默认按卷分目录：`正文/V01-卷名/0001-章名.md`。Codex 从已采纳的分卷计划获取目录，模板和长章合成使用同一路径，章号全书连续。卷名更新不会移动旧稿，已有平铺作品仍可继续；本功能不自动迁移现有作品。具体命令见[长篇流程](long-form.md)。

恢复顺序是查看当前任务和授权范围、作者已选与未决项，再处理来源漂移或待登记稿。允许写正文时才读取章纲与原文继续写。聊天中的旧描述不能替代作品文件；next_unit 是登记顺序，不是写作许可。

0.7新作品默认schema6，用changes保留未变项。明确新长篇可init --mode long；旧作品先long-enable-preview，按实际授权long-enable启用分卷并保持原协议（schema1迁移2）。旧schema1用snapshot，2–6用changes；不要把召回切片当完整快照。见[长篇流程](long-form.md)。

## 阶段、允许范围和作者决定

阶段包括方向、全书结构、分卷、章纲、试写、正式写作、修订与暂停，可以从正文返回规划。工具记录 stage/task/allowed_actions/draft_range/revise_range/stop_conditions/planning；阶段是工作中心，动作和有限区间决定能否登记。试写必须有末章和复盘条件；条件文字由代理落实，程序不能自动判断任意自然语言条件已发生。

新章或跨卷续写的细纲还不存在时，先登记`outline`阶段、仅`discuss/plan`且两正文范围为null的规划任务；`planning.outline`可用`status: draft`、空`refs`并列出待办。Codex通过`plan`建立真实细纲、核对实际采用后，再以当前revision登记`adopted`引用及有限`trial/drafting`范围。`refs`中的每条路径都须已经存在；`adopted`还表示真实采用，文件存在本身不能证明作者已采纳。已有合适的滚动细纲可以引用，不要预填尚未创建的未来单元文件、建空壳文件或刷新哈希绕过检查。这是在已有任务授权内落实顺序，常规命令不需要重复向作者确认。

临时任务放在workflow及交接/研究记录，长期定位、文风和权威规则只放稳定的世界与表达约束。不要把“这轮只写1–3章”写进这三份默认消费的设定文件，否则下一轮会同时读到旧范围。若旧文件已混入阶段性文字，保留原字节与证据，先核对当前正式任务和作者实际新指令，说明哪段是历史任务；确需改来源时走版本/影响流程，不直接覆盖已消费来源或改哈希。

例如六章后你说“暂停正文，先讨论总纲”，Codex 应保存该指令并正式登记；status 显示 next_unit=7，同时建议处理总纲。context --purpose discussion 不需要第七章细纲；正文 context、record-template、record 会拒绝越权。更晚的新授权可更新范围；不根据过去写过章节推断无限授权。

重要选择使用稳定 ID，逐项列已确认、候选、排除和未决内容，保存真实作者原话与本地来源哈希。可以说“宗门只选青岚宗方向，技艺先炼器；经名和住舍人数未定，小盾仅推荐”。decision current 应分别展示这些状态，decision list 查取代与原话记录。确认决策取代仍限同主题、同范围；设定文件的按章版本通过 source 管理，两者不要混淆。

作者计划与正文事实 ledger 分开。原话证据冻结后，原讨论文件可继续追加；工具核查证据字节，不自动理解作者意图或认证作者身份。不能编造会话 ID、把整份讨论稿自动升级为定案，或把手改的“当前设定”Markdown 当结构化确认。可读入口以正式命令返回的视图为准。

规划各层可为 missing/draft/adopted/deferred。adopted 要有来源，但有文件不代表已完成或作者采纳。远期允许在有限试写中 deferred 并写原因；不用为了开写把占位大纲标为已采纳。

试写结束转回讨论时可以保留 deferred 及原因，不需要伪改成已采纳。暂缓状态本身不授予正文权限；若带着暂缓项继续写，仍须有限 trial 范围和复盘条件。

“待核”“未回收”不等于漏洞。记录已知边界和下一步，不为让清单好看而提前结案。检索只帮助定位，回收早期线索仍须回读原文。

新增待核项要写清具体对象、最后确认的来源或位置及下一步，放进作品追踪或恢复说明，让新会话能接住。文字同源的不同纸本分别核对；“后续去向未核”不能写成已丢失或已销毁。追踪通过正式命令登记，不手改权威状态。

多处旧章修改后，不仅检查新正文，也要检查后续人物所知和物件保管。已经交接，人物条目却还写“明早待签收”，会误导下次续写；但未在现场的人也不能自动知道接收结果。让 Codex 按实际在场、看照或转述逐项更新，并把旧时知识标明章次。具体恢复、回退、召回和语义复核步骤见 [长篇工具用法](long-form.md)。

同一设定需要分章生效时，可以直接说：“从第10章采用新版，前9章保留原输入；先固定真实旧版、分析影响，再执行授权修订。”Codex 负责核对旧版的发布区间和回放来源。出现 SOURCE_BASELINE_REQUIRED，表示保留的旧章还缺原版发布区间，应找回真实旧字节并补齐，而不是刷新哈希；全部旧消费者都纳入本次修订时无需多做这一步。详见[版本与修订手册](revision-and-sources.md)。

## 旧稿导入与换位置

当前支持明确排序的 UTF-8 Markdown/TXT 分章文件。合订本先另存拆章副本，保留原文与位置映射；不要覆盖原稿。导入新建空作品，冻结原文，逐章实读和登记。未读的范围不能宣称已分析。

原文件移动后：

1. 查看 `import-status` 的 `can_continue`、`blockers` 与具体路径。
2. 如果只是换目录，准备 unit/path 映射，使用 `import-relink`。工具要求新位置的内容与冻结副本哈希完全相同。
3. 再查看状态并继续导入。重定位单独记历史，不改正文、冻结清单或已登记来源。

自然语言示例：

> 这部作品的旧稿移到了 D:/我的小说/原稿。先检查导入状态，按章节核对新位置与冻结副本是否完全一致；一致的用正式重定位命令恢复，不手改状态或来源清单。有内容不同的单独报告。

如果内容也变了，这是版本变更，应明确选择基线与修订方案，不能当作换路径。具体 JSON 见 [命令说明](workflow.md)。

## 修订和去 AI 味

明确希望“只报告”还是“直接润色”。修改已登记章节前查看修订号、核实最早影响范围；schema4及以上（含当前6）先revision begin，在独立区实读、rewind、修改和逐章重登，完整尾段复核后prepare/commit。主稿不提前覆盖，旧报告不能直接套新正文或依赖。

去味流程见 [专项指南](deslop.md)。它关注可观察的阅读问题，不追求检测器分数。单个词、比喻、长句或议论不是自动错误；不同文体使用不同标准。

语言审查也覆盖“意思能猜到，但搭配或关系含混”的句子：如许可动作挤成数量短语、连续用“少许/空缺/留多少”省掉必要对象、把人物顾虑写成空泛安排。报告应逐条回应点名原句，并复核漏检和误伤；对象明确的省略、符合职业的计算对白和成立的文学修辞应保留。缺少前文时列待核，不补造设定。[去味流程](deslop.md)说明成对示例和新版规则的读取位置；更新过的作品从 `.writer/tool/.agents/skills/writer-review/` 读取，根目录旧技能与作者定制仍保留。

revise_range须覆盖最早影响章至原末章，但直接改写情节与后续实读重登是两种范围：只授权改第2章，不能据此随意重写第3章以后的剧情。确需扩大原指令范围时先报告，已有明确授权不重复索取。schema3保留原回退兼容；schema4及以上主稿不允许直接rewind。跨会话用ID/令牌恢复；并行冲突保留双方，不自动合并。设定改动先固定真实旧字节，未来版按章发布；历史变化持久阻断，随完整修订一次提交。详见[版本与修订手册](revision-and-sources.md)。

## 跨章复核、登记预览和意见闭环

比较重复须完整阅读实际范围，逐章说明目标、阻力、选择、后果和关系变化，以原句作证。共词或相似行动不自动等于文学重复；模型说明相似结构、不同收益、保留项、可选调整及不确定性，缺证填unknown/none及原因。review-template填当前范围和哈希，模型完成后review登记；脚本只验记录，不给文学通过或重复率合格。

record-preview列缺项和实际差量，不登记、不生成journal、不补空摘要、不刷新来源哈希。新稿用写前record-template；schema5及以上历史修订在独立区回退后用revision replay-input恢复旧摘要、changes与引文草案。路径、当前context哈希自动填，未变项保留；实际读稿核承接后填写replay_review真实报告及六项checked_fields，先preview再record。旧引文消失或正文再次变更仍拒绝，草案不能当“无变化”结论。

预览还会列出与本次变化角色有关、但尚未更新的知情条目，最多8个并标明遗漏数。让Codex按需回查：例如人已送回家，另一个已闭合线索里却可能还写着等待回程。关联只是复读候选，不自动证明有错；明确的历史说明可保留，当前知情变化则按实际正文补差量和引文，不重抄全快照，也不改不可变观察。

重登草案会按原来的真实变化恢复字段和逐人的知情差量，避免后章整张旧知识表覆盖前章修正。它仍是待核草案：实际变过的整段说明、人物状态及物证去向，要由Codex实读新旧正文后决定如何承接，工具不会自动合并剧情含义。

独立修订发布还会与会话建立时的原始基线比较观察条目；即使回退到观察首次出现之前，整段重登也不能删除原观察或改其type、statement、author_truth。读者及人物所知、状态可据新文更新，解释或纠错另建条目。遇到IMMUTABLE_OBSERVATION_CHANGED，按错误中所列ID核对原记录与新解释，不改旧字或原哈希来通过；中断事务的complete也执行此核验，rollback仍可恢复原字节。

context、record-template、record-preview、review-template、replay-input可选--out保存.writer/drafts下新JSON，不覆盖旧输入，不作正式设定来源。活跃修订的输出在所属独立区带令牌完成，正常作者无需查找UUID或手填哈希。

意见区分correctness/continuity/readability/optional_style、严重度、置信度及原句建议。review-issues resolve分别记adopted/retained/deferred与真实作者原话或代理既有授权；代理不冒充作者逐项确认，仅审查不能借采用获得改稿权，可选风格只作suggestion。

跨章取证可能只需改后一章。例如第42章作参考，错误只在45章：代理resolve的采用授权仍按全部证据章保守检查。若45章已在合法独立区实际修好并提交，原意见因范围保护未能先采纳，可让Codex用`review-issues acknowledge`核真实提交、显式45章目标及未变42章参考，记录“现在接受已有修复”。它适用于open或仅由代理延期、且没有既有采纳历史的高置信事实/连续性问题，不覆盖作者保留、作者延期或可选润色；不删除旧证据，不倒填采纳日期。补登记后仍要用覆盖全部原证据章的当前有效实读报告verify，不能直接算已解决。详见[专项手册](review-and-registration.md)。

采用后按范围实改并正式提交，apply核旧稿、当前新稿和已完成事务，默认须对应正文实际改变。若原文正确、登记摘要或时间线有误，可说明“只修登记，正文不动”：Codex仍走独立区修订和尾段重登，提交后在apply的JSON中显式设置`"change_scope": "tracking"`，绑定对应章节的真实追踪变化；不靠改空格、刷新来源或等价重登冒充修复。verify仍须当前有效、覆盖相关章节的模型实读报告，联合核对正文和追踪，记录verified或needs-recheck。再次修改相关正文、追踪或依赖，旧verified显示需重核，历史保留；retained不等于修复。意见动作推进revision，旧登记输入可能过期，应重读后准备。见[专项手册](review-and-registration.md)。

意见已事先采用时，apply允许未改参考章位于实际提交范围之外。例如采用时引用9、21章，只在21—60的独立修订中改21章：工具核真实事务归档、原采用基线与当前登记，确认第9章前后完全保持，再自动区分参考章和目标章；无需新参数或重新采用。参考章正文或登记变化、旧事务归档损坏、提交未改意见对应正文，仍会拒绝。最后verify报告须覆盖9和21，参考章以后变化仍显示需重核；不能把“未改参考”当成已修改章节。

## 保留与备份

关闭会话前保存正文、登记结果和未完成事项即可，不必为了“清零”删除候选、旧报告或未收伏笔。新会话若只获恢复/讨论授权，先报告当前任务，不能因next_unit存在而写下一章。

独立修订区不含随附工具包。0.7.2的doctor识别其合法父作品，检查父包并报告revision_context，读取诊断不需要所有者令牌，也不会修改正文或状态。父包损坏、协议不符或执行构建与会话绑定不匹配仍失败；不能为了通过诊断向分支复制工具、改构建ID或覆盖state。旧0.7.1在合法修订区可能报缺少.writer/tool，从新主项目入口诊断并核实际绑定，不将该报错当成稿件丢失。

保留整个作品目录，以及需要留存的外部原稿和导出目录。 `.writer/` 保存权威状态、差量记录和回退备份；`.agents/` 保存随作品使用的技能。原稿与审查报告建议按版本另存，不覆盖已经绑定哈希的材料。

0.7新作自带完整轻量工具、包内技能/手册/示例/许可和构建清单；不包含主项目质量引擎。旧协议不自动迁移，新主项目可显式传--project按原协议操作；需新能力在已授权副本迁移3、启用保护4、review-workflow启用5，再按工具更新任务显式enable至6，保留各次备份。旧0.6拒绝6。不手改版本号降级或自动迁移现有作品。

更新由Codex根据[更新手册](tool-updates.md)准备输入：明确本地来源，先只读计划，确认实际授权、revision与包指纹，再从外部入口替换。根AGENTS/技能/手册笔记默认保留，包内资源与新入口配套；选用包内技能须由当前任务决定，不自动改写作者定制。受管包被定制、未知文件、活跃修订、正文漂移或第三方改动都会阻断。中断后普通入口停止；外部tool updates列事务，按现场证据完成或回滚，不自动抢锁、不清理备份。成功更新只增加一次revision及工具generation，不改变文学事实、章节消费来源或正文授权。

tool identify/compare只读报告内容指纹、版本号、模块/文档/技能差异及初始清单状态；更新另外使用上述update-plan/update/recover流程。随附副本有意不含完整引擎，profile差异单列；0.1–0.6无清单旧副本只报观测值，不伪造来源commit。0.7包应有清单，缺失属于损坏。指纹不是供应链签名或作者身份认证。

0.7.1还核对已安装的完整内容身份，重建清单不能追认变化。发现清单丢失或TOOL_INSTALLED_BUILD_MISMATCH时，保留原包、state与备份，从外部入口核原版，不能修改指纹绕过。恢复途中再次中断，继续使用原事务，核实际遗留锁后明确complete或rollback；完成后同方向重试不重复增加revision/generation。实际旧作品升级须有范围明确的授权，查看doctor不会自动执行。

随作品保留的许可、来源清单与原文哈希见 [来源与许可](attribution.md)。历史来源清单不表示清单中所有主项目组件都已随作品复制。

## 命令使用者：报告与输入容量

### 长篇上下文

超出工具预算会返回`CONTEXT_BUDGET_EXCEEDED`和`context_budget`：`limit_chars`、`required_chars`、`over_by_chars`给出预算与实际差额，`sections`按占用排序，`largest_sources`最多列十项设定/研究引用及各自占用，更多项数见`omitted_source_count`。明细不附正文；各分项是独立JSON序列化长度，包含字段名和分隔符的总量另算，不能直接相加。计量是紧凑JSON的UTF-16字符单元，不等于字节或模型token，也不是实际模型可容纳容量的保证。

先检查大项与本章引用是否相关，再整理可选资料或显式提高`--max-chars`。作者授权、核心设定、当前状态、显式召回与到期线索仍保留；修改已消费来源仍须影响分析。失败不改state、不生成out，授权不足和来源漂移仍优先阻断，不能用加预算绕过。

显式扩容成功后可继续取登记模板、预览和登记，不需要向这些命令传`--max-chars`。它们完整核对来源与授权，不将上下文显示预算用作内部登记上限；单文件及内部状态的容量、来源哈希和修订保护仍然生效。

context的`--max-chars`控制工具生成上下文的字符预算，与Codex单次工具结果的显示容量不同。扩容成功不保证一屏能显示完；也不要把显示截断误认成工具已经丢掉原文件。可用`--out .writer/drafts/context-本次.json`保存新的可读入口，再按段核对返回内容、预算及`omitted_ids`，按需要recall并实读原文。`--out`保留完整返回结构并增加output路径，不提供精简stdout模式；不要将完整JSON一次性塞回显示窗口，也不要覆盖上一份已绑定输入。

长输出发生截断时，保留原始输出和已读范围，补读缺失部分后再判断。读取摘要、字段或保存的路径不能代替完整正文；完整连读报告须基于范围内当前版本的实际全文阅读。context预算不足、正文未登记、来源变化和服务中断分别核实，不重新初始化作品或手改哈希来“恢复”。

### 审查报告容量

普通审查与旧章重登报告使用非空UTF-8文本，单文件最多1 MiB，按实际字节计；普通摘要、角色状态及比较字段保持原短字段限制。修改已登记报告或依赖后须重新核读并登记。超上限时保留原文，整理覆盖同一实际阅读范围的重点报告，不缩小声称范围或填表冒充完整复核。该限制由Codex准备输入时处理，新作者无需手工计算哈希或拼接报告。
## 独立候选已有下一章稿件

旧修订会话不能用更宽 workflow 授权扩展。已有封存稿时，按[来源与修订说明](revision-and-sources.md)的“独立候选的下一章采纳”一节派生新候选，完整承接原消费链，再显式采纳登记。原候选、原工具和主稿均保留。新候选仅允许指定下一章；旧章只读，再下一章、prepare/commit 均拒绝。不要用后来取得的 record-template 追认动笔前准备。
