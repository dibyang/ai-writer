# 长篇工具用法

完整命令、分卷 JSON、增量登记、证据、滚动审查与旧作导入示例保存在随作品复制的 [长篇流程](../.agents/skills/writer-project/references/long-form.md)。作者任务入口见 [使用手册](user-guide.md)，具体命令帮助支持 `命令 --help`。

已有作品先运行 `node bin/ai-writer.mjs status --project 目录`。尚未启用长篇追踪的 schema 1 作品可用 `long-enable --expected-revision 当前号` 迁移，工具保留旧状态备份；已是 schema 2 的直接恢复续写。schema 1 仍兼容，schema 2 增加分卷和差量 journal；不要手改 `.writer/state.json` 或删除 journal。

0.5 新作品默认 schema 4，先恢复任务/授权/作者选择、版本及活跃修订。schema 2/3/4 共用 changes/journal；4 的 long-enable 只启用分卷契约，不降级。未启用分卷不强制每篇散文配置卷纲。旧作品不自动迁移；本批无安全更新。规划时 context --purpose discussion 不需要下一章细纲。设定版本、历史影响和独立修订步骤见 [专项手册](revision-and-sources.md)：继续复用本页的分卷、物证、知情和滚动复读，不另建账本。

`outline --unit` 与 `context --unit` 自动取当前卷/剧情单元；`recall --query` 用来定位早期线索及正文；`record-template` 返回 changes 格式。`check` 同时校验差量链并报告滚动审查欠覆盖。所有导出仍是草稿。

`rolling_review.stale` 保留所有失效历史记录数；其中 `stale_with_current_coverage` 表示已有一份当前有效报告完整覆盖该旧记录的阅读范围，`stale_without_current_coverage` 表示尚无这样的报告。分段报告不能拼作一次完整连读。旧记录不会重新有效，也不应删除历史来清零；需要补做的每三章滚动窗口看 `pending_windows`。回退后尚未重登的章节也可能落在旧报告范围内。上述数字只表示版本与阅读覆盖，不表示文学质量通过。

分卷范围是全部文体通用的连续单元号；小说一般按章，剧本可按场/集，历史散文按章。物证/人物知识账本按任务需要使用，不强迫散文采用小说结构。历史事实仍必须经过原来的 research_refs 事实卡流程，ledger 不替代史料核验。

当前卷纲哈希按整文件保护，已消费卷纲的任何修改都需核实影响后回退；未来章纲可滚动细化，尚无卷内未来arc免回退的细粒度修订。旧稿输入只支持明确排序的UTF-8分章文件，合订本先保留原文并拆章。修订报告建议另存带修订号的新文件，保留原报告，旧覆盖不会自动升级为新稿结论。

Windows 本机既有实跑中，Codex CLI 以嵌套作品目录为 cwd 时曾遇到 helper 启动失败；从 ai-writer 根目录启动并显式传作品路径后完成恢复续写。遇到同类错误时使用根目录入口，不修改全局安全设置。独立作品的 Node 轻量工具可用于诊断；具体历史证据保存在主项目 acceptance/20261015-long/。

旧稿移动后看 import-status 的 can_continue/blockers，用 [import-relink](workflow.md) 绑定同一冻结内容的新位置。正文目录内的未登记稿由 status/check 主动列出；导出时核对 excluded_drafts。

## 新会话怎样接住旧章修改

先检查当前状态、正文与来源漂移，再读取当前卷纲、章纲、相关人物和原文。跨卷回收至少回读线索首次出现、最近变化及本次兑现处；恢复说明应列出人物分别亲见、看照、听述了什么，原物由谁保管，哪些仍只是约定。不要从旧聊天或修前报告补回已被改掉的情节。打开旧章时沿用召回证据中的 `draft`、只读状态的 `units[].draft` 或实际目录列出的路径，不凭记忆拼接标题；标题已改而登记路径保留时，仍按真实路径读取。

修改多处旧章时，先保存修前正文、状态和登记输入，找最早受影响的已消费来源，再正式回退重登。最早正文变化和最早来源消费者可能不同：全局规则在第1章已消费，即使物件第3章才出现，也不能只从第3章处理。比较回退前后全部稳定ID、观察事实、到期值、证据与知识，未改原句的证据应保留并绑定当前正文；不靠推迟到期或删除未知项清零。

正文和资料同时漂移时，`context`、`export` 返回 `CONTEXT_CHANGED`，`recovery.from` 汇总两类文件影响的最早单元，`recovery.expected_revision` 和 `next_command` 给出可核对的恢复指引。先看 `status` 的全部 `stale_units`、`changed_sources` 并备份，再按核定范围一次回退、逐章重登；回退保留正文，不会自动修好后续语义。只改追踪摘要中的错误而正文、资料字节未变时，状态检查可能正常，仍应从首次错误的单元正式回退修正，不能在后章添加新告知来掩盖早章本不可能听到的话。

| 变化类型 | 当前和历史怎样记录 |
| --- | --- |
| 剧情中原物从柜上搬进柜内 | 保留当初柜上和后来柜内的时点，区分亲见、电话获告及未检查内容 |
| 作者追溯改变当初一笔门费 | 从首次报价同步该笔后续金额及人物历史串，修前值保留在备份中，其他独立款项不变 |

证据身份不能只用 `unit+line`：一行可能有同一ID的多条不同引文，迁移时按ID、单元、引文和版本逐项核对。引文仍是子串不等于原事实未变，例如“二百”也出现在“二百四十”里；金额、对象和条件需连完整句子实读，有意改变的引文另列改前改后。把材料放大成两页、另印四页或加电子页次，都不自动证明旧单页已收回；待核对象写清最后确认的来源与范围，进入追踪或恢复说明后再续写。

## recall 的查询范围

`recall --query` 在账本ID及内容、章节号及摘要中做不区分大小写的关键词定位，不搜索完整正文，也不进行语义理解。空白分隔的词必须**全部匹配（AND）**，并非多个ID任选其一；把 `T_SIGNAL T_TAPE` 拼成一次查询可能没有结果。

```powershell
node bin/ai-writer.mjs recall --project works/雨夜来信 --query T_SIGNAL --limit 20
node bin/ai-writer.mjs recall --project works/雨夜来信 --query T_TAPE --limit 20
```

整项查询去掉首尾空白后与账本ID完全一致时，该条优先返回，匹配不分大小写；其他匹配仍按原顺序。`total` 是全部匹配数，`omitted` 是未返回数。多ID按项查询，或在章纲的 `recall_ids` 数组中显式召回。`--limit` 默认20、允许1—100，是返回条目数；`--max-chars` 只用于 `context` 的字符预算（默认40000、最低1000），不传给 `recall` 或 `record-template`。`recall` 结果及 `context` 的 `omitted_ids` 都只是定位线索，相关正文仍须实读。

## 回收后还要检查人物是否真的知道

同一事件可能分布在主线、物件、观察、读者总览及人物快照中。仅更新 `status`、`custody` 或 `reader_known`，仍可能让 `character_known` 停在“明早待签收”“尚未听过”。实际完成交接、补录或查访后，逐项核对关联条目的当前知识，而不只检查主线是否 resolved。

把当前知识与“截至第几章”的历史分开；保留仍有效的内容，不把过时的未来计划留在当前结论中。罗敬未参加第4章原带短听，与第23章已听完整工作转录可以同时成立。陪运后离场、看照片、听电话都不等于亲见签收；作者知道最终保管人，也不能自动同步给所有角色。知识更新应有实际正文和版本绑定引文支持。

保留历史不等于无限复制整段旧摘要。可以精炼当前知识，但要逐项比较仍有效的信息和证据，历史原记录由journal与修前备份保留。`check`、引文哈希以及滚动审查覆盖只做机械核验，不能发现全部语义陈旧，也不保证旧报告中的账本结论适用于新的追踪状态。

首次承诺里的“尚未完成”可以是真实的旧时点，应以章次及当前 `reader_known` 说明后来进展；当前总览不能一直停在旧计划。`due_unit` 是作品单元号，不是故事中的日期；一次有限试行、一次收款或一项告知的兑现，按原项范围结案，未核读者、其他副本和未来安排分别保留。只看到人离开或收到“已到家”消息，也要分开写清已见动作与当事人口述。

`review`绑定的报告保存在作品的`审查/`目录；阶段日志、核验脚本和导出可另存指定目录。报告应区分实际阅读、机械检查和未证明事项。完整实例见 主项目的 `acceptance/20261016-expanded/README.md`（验收目录不随独立作品复制），其中r63机械通过后仍发现知情陈旧，经正式修订到r67才完成本轮复核。

审查输入的 `source_hashes` 必须对应整个 `from`—`to` 实读范围。构造完整映射、核对全部正文路径及数量后一次登记；循环内先交一章哈希会被拒绝。截断输出应补读，改过正文应重新实读并绑定当前版本；整体报告只能覆盖真正读完的范围。新增未核范围也应进入续写入口，不只埋在旧报告旁注。主项目的 `acceptance/20261016-hundred/README.md` 保留更大规模的连续性实例及当时边界，不随独立作品复制。

长篇增加篇幅靠行动、人物选择及生活后果展开。若连续数段用相同否定式边界收尾却没有新变化，应结合阅读代价诊断，不能将单个“没有”、比喻或长句一概删掉。追踪表承担核对，正文仍需保留人物各自的口气和有效修辞，按[去AI味流程](deslop.md)定点处理。

把追踪信息转成正文时，账本中的章号、ID和审查结论仅用于定位与核对。人物不会因为作者写到第几章，就在自己的本子上记“第几章的纸”；改用其实际知道的日期、版本特征或自然称谓。报告里的章号索引可以保留，也不禁止人物谈论他们正在读的书。知情边界先落实为场景和追踪记录，避免在每一段尾部重复解释“不能自动同步”，挤掉人物当下的动作与关系。
