## 长篇重点：从机制到实现

| 问题/参考机制 | ai-writer落点 | 关键边界 |
| --- | --- | --- |
| 分卷承诺、阶段储备、当前剧情单元切片 | lib/longform.mjs：volume/outline；章纲arc_id | 分卷范围互斥，卷内剧情单元连续；计划不自动兑现；不强制爽文比例与固定高潮章位 |
| 完整旧快照反复增长 | lib/journal.mjs：schema 2、可逆差量、显式迁移 | 原状态先备份；state为提交点；append数组不反复复制历史；恢复核对差量链和哈希 |
| 旧线索忘记、热上下文失控 | context/recall/recall_ids | 显式/置顶/到期未结全部携带，可选关联最多12条；省略ID公开；证据首条与最近两条，完整历史可回查；预算不足拒绝 |
| 作者真相、读者揭露和人物认知混淆 | ledger.author_truth/reader_known/character_known | 分区输出；人物所知只取对应映射；未登记不是“知道”也不是“不知道”；仍需实读判断 |
| 物证转手与观察被后文改口 | ledger observation/object、custody、previous_holder | 引文须存在于真实正文；观察本身不可逆改；交接原保管人须匹配；这些结构检查不能证明动作语义正确 |
| 中断后靠聊天记忆接写 | status→outline/context→逐章record | 当前state恢复，不从未来卷纲补事实；每章串行推进；重复相同登记幂等 |
| 旧作导入被当“新书对标” | 冻结副本、逐章import、源漂移检测 | 只读源文件；导入角色固定own-work-continuation-baseline；未读/未登记范围如实保留 |
| 审稿台账绿灯代替完整阅读 | review/check.rolling_review | 每3章建议连读当前3+前3，记录报告和正文版本；自动入口仅model-self-review，不产生真人验收 |

## 结合既有作品经验做的调整

1. 本地小说审修形成的“每三章滚动六章”用于跨章承接，和单章自检互补。覆盖记录必须对应实际版本，机械搜索不能冒充语义阅读。
2. 现正文与当前追踪优先于旧计划；状态词“待核/待定”本身不是漏洞。账本允许pending/partial/intentional-open，保留证据边界与后续路径，不为报表归零把悬疑提前结案。
3. 物证生命周期和不可变观察结合：新证据可以改变解释，不能让原来可见的针脚/裂口后来消失；换手要求原保管人与正文锚点。对误推断的修正另建条目关联，历史可回查。
4. 剧本仍按可表演行动与空间道具核对；历史散文继续事实卡、史源依赖和推断边界。长篇工具增加组织能力，不让四种文体共用小说心理或网文追读门槛。
5. 参考中的作者记忆有明确来源/范围思想值得保留，但本轮只维护作品定位与文风，不新增全局记忆、自主观察作者或跨书传播偏好。

## 保留但没有移植的能力

全量拆书的阶段调度、跨书机制索引/灵感库、跨书偏好仓库、市场采集器、专用浏览器管理、多宿主hooks、封面/发布管道和自定义代理编排均没有接入本轮运行。13入口盘点不等于13能力均实现。当前实现聚焦长篇的可恢复状态、相关材料装配与实读记录，后续需求可沿本清单扩展。

测试与真实创作结果见 [本轮验证记录](../acceptance/20261015-long/README.md)。该记录区分合成容量、工具回归、Codex语义样稿、真人/市场/作者验收，不把任一局部结果扩成完整长篇质量保证。
