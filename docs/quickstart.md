# 快速入门：先完成第一章

已有受保护续写候选的第七章登记后需要小修时，使用[版本与修订手册](revision-and-sources.md)中的“已登记第七章的小修与重登”。先建立独立区、固定来源，再按封存稿重登和复核；不要直接修改旧候选或更新其中的工具。

ai-writer在Codex中使用：你说明任务，Codex阅读文件、写作和登记；正文与追踪都保存在本地。准备好可以使用的Codex和Node.js 20或以上，无须安装npm依赖。第一次先用一个新目录，已有作品的导入或升级另走专项流程。

工具自有部分采用Apache-2.0，可依许可使用、修改和再分发；第三方资料保留原许可。使用工具不会改变你作品的权利归属。分发工具时保留完整许可资料，详见[授权与来源](attribution.md)。

## 1. 打开ai-writer，发出第一条任务

在Codex中打开ai-writer主项目目录，将下面的作品名和要求换成自己的：

> 创建小说 works/雨夜来信，面向普通读者，计划十二章、两卷。先完成定位、人物、核心谜面、全书骨架和两卷目标，只细化近期前三章。本轮仅授权试写第1章，写完暂停复盘。请正式保存这次任务和范围；完成自检、登记与检查后，告诉我作品完整路径、正文位置、已登记范围、未登记稿和下一步。不要自动写第2章。

这是发给Codex的创作任务，不是终端命令。想先讨论，可把“试写第1章”改为“只讨论规划，不写正文”。远期允许保留骨架，无需先写完十二章细纲；初始化说明文件存在，不代表规划已完成。

本轮写到哪章、何时暂停等临时范围，应由Codex保存到正式任务状态和本地交接；不要写进作品定位、文风或权威世界规则。长期设定只放稳定的故事约束，避免下次续写时还读到“只许写第1章”的旧任务。

若尚未确认环境，可先在主项目终端执行：

```powershell
node bin/ai-writer.mjs doctor
```

`ok: true`表示工具文件检查正常，不表示文学质量通过。首次使用不用填写JSON、哈希、schema或修订令牌，Codex会依据你的实际指令准备必要输入。

## 2. 看交付，再决定下一步

每次结束应收到：作品完整路径、实际正文路径、已登记范围、实际审查范围、未登记稿或阻断，以及当前允许的下一步。先读正文；“文件已写”“已登记”“已审查”“作者定稿”是不同状态。

看完第一章后，继续在同一会话或新会话说：

> 恢复作品 works/雨夜来信，先核对当前任务、已登记章数、未登记稿和待回收线索。本轮授权写第2章，完成后暂停；不要覆盖已有正文，不把约定当作已发生事实。

也可以只恢复而不续写：

> 恢复作品 works/雨夜来信，只报告当前阶段、允许范围、作者已选与未决项、活跃修订和下一步；这轮不新增正文。

暂停规划可以说：

> 暂停正文，先讨论全书总纲并保存这次任务。投递员的身份已经确定，寄件动机仍待讨论；请分别记录已选和未决内容，下一会话不要自动续写。

新章细纲尚未创建时，让Codex先保存仅规划的任务、不开放正文范围，用已有真实来源建立细纲，再登记实际采用的引用和本轮有限正文范围。不要把未来文件先填成已采用引用；遇“引用不存在”应保留失败输入并纠正顺序，不建空文件或手改状态来通过检查。具体字段顺序见[阶段与授权](workflow.md)。

保留整个作品目录，包括隐藏的`.writer/`和`.agents/`。只复制正文不能完整恢复状态。长篇后续按[从规划到导出的完整路径](long-form.md)走，跨会话只凭文件恢复，不依赖聊天记忆。

## 3. 审查、修订和导出

遇到局部问题可以直接说明，不必知道技能名称：

> 这部小说想写长篇，先检查已有点子能否持续产生不同选择与后果，明确本卷能兑现什么。保留我的题材方向，只滚动细化近期三章，这轮不写正文。

> 只审查第2章结尾和第3章开头是否接得住，核时间地点、人物伤情和知情，不为追读强加危机；给具体问题与应保留项，暂不修改。

Codex从doctor返回的`skill_root`按需读取`writer-novel/references/story-development.md`（长篇方向）与`writer-novel/references/scene-connections.md`（局部诊断）。已有作品更新后仍保留根作者定制，新参考应从当前包读取，不能假定根技能目录已有新文件；其他文体继续使用自身规则。

若长章总像剧情提要，可以说：“在已授权范围内，按已有细纲分段展开这一章，合章后完整复读，再回对本章目标、实际变化和禁止提前揭露项。不要增加新设定，别把中间段落当成新章登记。”Codex按需读取同一skill_root下的`writer-novel/references/chapter-delivery.md`；普通章不用额外做表。

分段写到一半要换会话时，让Codex保存实际片段路径、写前模板和未完行动到本地交接。新会话先核对任务状态，再读取交接及原片段；没有完整章可登记时，不因正文清单为空就重写或跳到下一章。

任务分几次运行时，把整段授权和本次断点分开说明。例如：“本轮授权37—39章；这次先完成37章，保存38章的前两段后结束运行，下次恢复并完成39章后暂停。”创作阶段与范围记录完整的37—39章任务，交接另记本次停在哪里。运行结束不等于作者撤销后续授权；作者明确说“暂停正文”时则必须按暂停恢复。

恢复半章时，已登记状态仍停在上一章；未登记分段里可能已经完成了新行动。先实读分段，再从真正未完的位置续写，不因账本还没更新而重复修门、交钱等行动。状态、来源和模板均未变化时沿用写前模板；不要为换会话重取模板或改任务来补写记录。发现真实变化则先核查影响，保留旧输入和分段。

确认问题已通过正式修订改好，但意见仍显示未处置时，可以说：“核对原意见和真实修订凭据，补登记已经发生的修复，再用当前完整读稿报告复核；保留原取证，不伪称我事前逐条采纳。”Codex会区分需修改的章和只读参考章；条件不符时保留诊断，不为闭环重新制造错误。具体边界见[审查与登记说明](review-and-registration.md)。

如果意见已经事先采用，只需修真正有错的章节。例如引用第9章对照第21章，而错误只在21章，可以从21章开始正式修订；提交后Codex照常绑定原意见和实际提交，工具会核第9章在修前、修后及当前均未变，保留它作参考。无需多改第9章或删掉引文，最终复核仍须读到两章。

需要合章时可说：“核对分段顺序和版本，用 assemble 另存完整章，保留原片段；全文实读和纲文回对后先保存报告，再预检、登记，任一步失败就停止后续步骤。”输入片段放`分段/`，合章目标必须是`正文/`下尚不存在的`.md`或`.txt`；不能把合章写回`分段/`。已有目标先实读比较，另取`正文/`下新路径，不覆盖。工具只连接原文，不自动改写或判断文学质量。

需要保证报告先于登记保存时，让Codex在登记输入中加 `draft_review`，绑定报告路径、审稿人及完整章和报告的SHA256；缺文件、空报告或版本不符会阻断。普通作者不用手填哈希。原流程仍兼容，机械登记成功不等于已经审稿。

已登记章节修订后，可以说：“以正式修订后的完整章恢复，保留旧分段和旧交接作为历史。需要继续分段时另存当前版本，核对合章与修后正文一致，并新建当前交接。”工具不会自动同步`分段/`和旧交接；不要直接用旧片段覆盖修后正文。

只审查：

> 完整阅读这两章，检查连续性、重复解释与人物口气，只报告具体问题和应保留的表达，不修改正文。

新长篇正文默认保存在 `正文/卷ID-卷名/章号-章名.md`，让 Codex 使用上下文和登记模板返回的路径即可；不必手动拼目录。已有平铺稿不会自动搬迁。

授权修改已登记章节：

> 在独立修订区润色第1章，保留情节、事实和人物声音；先核对需要重登的后续范围，如超出这次授权则先报告。完成实际修改、后续追踪复核和提交，保留原稿与改前改后对照。

旧章修改可能影响后续登记；“只改第1章”不自动授权改写所有后续情节。让Codex说明影响并使用已有授权，不直接改主稿或补哈希。去味方法见[去AI味流程](deslop.md)，意见处置见[复核手册](review-and-registration.md)。

觉得句子“能猜懂但别扭”时，可以说：“逐条审查这些原句，查含混搭配、缺少对象的概括和不自然对白；复核漏检与误伤，保留正常省略、修辞和人物口气，只报告不改正文。”Codex应结合上下文给问题、保留或待核结论，不靠禁词判定。

设定分章生效可以说：“从第10章采用新版，前9章保留原输入；先固定真实旧版、分析影响，再执行授权修订。”若提示 SOURCE_BASELINE_REQUIRED，让 Codex 补齐真实旧版的发布区间，不能刷新哈希跳过保护；具体流程见[版本与修订手册](revision-and-sources.md)。

如果原文无误，只是登记摘要或时间线写错，可以说：“核对真实日序，只修正已有章节的登记追踪，正文不动；说明影响范围，按授权正式修订、重登并完成意见复核。”Codex会选择追踪专用闭环，不要求作者写JSON，也不用改一个空格来通过正文修改门槛。

已登记为观察的原字、类型和作者真相仍保留；回退到首次出现之前也不会解除保护。发现新解释或原记录有误时，保留原观察并另记修正，避免把后来结论写成当初就看到的内容。

登记前可以说：“看预览里的关联未变项，按实际正文检查人物所知是否仍有效。保留有日期的历史说明，只补真正变化的字段和引文。”关联提示是有上限的回查候选，不能代替模型实读或自动判错。

导出：

> 导出 works/雨夜来信 当前已登记草稿到作品目录外的新目录，核对未登记稿、回退留稿与审查覆盖，说明纳入和排除范围，不覆盖旧版本。

结果为`manuscript.md`和`manifest.json`；检查清单中的范围、排除项和警告。导出仍是草稿，不自动上传或发布。

## 其他文体与独立目录

| 任务 | 如何说明 |
| --- | --- |
| 剧本 | 创建screenplay作品，说明短片/剧集、预计时长，先梗概和场次规划，仅写指定场次；动作可表演 |
| 历史散文 | 创建history作品，提供明确历史主题，先核验史料和事实卡，再写指定篇；不编造对白、心理和现场 |
| 散文/非虚构 | 创建essay作品，提供真实经历或素材，说明声音与篇幅，区分事实、记忆和观点 |

历史小说属于novel，非虚构历史才是history。不要将小说的谜面、强压或章末门槛套给所有文体。

新作品自带轻量工具、技能和手册。直接打开作品目录时，在该目录终端运行：

```powershell
node .writer/tool/bin/ai-writer.mjs doctor
node .writer/tool/bin/ai-writer.mjs status
```

主项目用`node bin/ai-writer.mjs`并传`--project "作品完整路径"`；独立作品用上述随附入口，当前目录含`writer.json`时可省略`--project`。更新后以该入口`--help`显示的包内手册为准，作品根手册可能保留作者笔记。

不认识命令时，让Codex查看当前入口的`help`；单项帮助用`help record`或`record --help`。`help`也接受通用的`--project "作品完整路径"`，仅展示当前工具的帮助，不读取或修改作品，即使作品尚未创建也能使用。

独立修订区不自带运行包。新版`doctor`和`tool identify`会核对它所属的父工具及会话绑定；绑定不同或父包损坏时保留候选并返回诊断，不要自行复制工具进去。

更新也会保留作品根技能。新会话按根作者规则恢复，并从help列出的“当前工具流程技能”读取新版流程；doctor的`skill_root`给出本次校验的技能目录，`project_skill_root`是保留的作者技能目录。包内说明用于补齐当前命令和保护流程，不自动替换作者定制。

长篇的context可能超过Codex单次显示容量。可让Codex用`--out .writer/drafts/context-本次.json`保存新入口，检查预算和`omitted_ids`，再分段核读所需内容；该选项仍会返回完整JSON，不会自动缩短控制台输出。看到“输出截断”应保留原输出、补读未显示部分；声称完整读过的正文和必读来源必须实际读全，不能仅凭文件已保存认定读完。细节见[使用手册](user-guide.md)中的“长篇上下文”。

同一作品的写前context、登记模板和预览等带`--out`保存操作要依次执行，等上一条退出再运行下一条；它们会创建草案并取得作品写锁，不能当作独立读取并发。遇占用先核仍在执行的命令，正常结束后再重试；不要删除锁或刷新哈希绕过保护。

若工具返回`CONTEXT_BUDGET_EXCEEDED`，查看`context_budget`里的实际总量、分项和主要引用占用，再让Codex按相关性整理可选研究或提高`--max-chars`重试。失败不会截断上下文或生成out文件；不要删除作者约束、手改状态或重新初始化。这里统计序列化字符量，不是模型token数。

若Codex在嵌套作品目录出现`helper_unknown_error`，返回主项目会话并明确作品完整路径；不要重新初始化或修改全局安全设置。已有作品导入、版本变化、修订恢复和工具升级分别见[使用手册](user-guide.md)、[版本与修订](revision-and-sources.md)及[本地安全更新](tool-updates.md)。
## 已有独立候选卡在下一章登记

如果独立修订区固定为 1–6 章，增加正文授权也不能直接登记第 7 章。不要扩大旧 scope、改旧哈希或覆盖活跃工具。新版提供受保护的 `revision continue` 派生候选及 `revision adopt` 已有稿采纳入口，原主稿与原候选保留。先按[候选续写采纳说明](revision-and-sources.md)的“独立候选的下一章采纳”一节核实备份、来源、固定制品和单章授权；普通新作品无需执行此流程。
