# 快速入门：先完成第一章

ai-writer在Codex中使用：你说明任务，Codex阅读文件、写作和登记；正文与追踪都保存在本地。准备好可以使用的Codex和Node.js 20或以上，无须安装npm依赖。第一次先用一个新目录，已有作品的导入或升级另走专项流程。

## 1. 打开ai-writer，发出第一条任务

在Codex中打开ai-writer主项目目录，将下面的作品名和要求换成自己的：

> 创建小说 works/雨夜来信，面向普通读者，计划十二章、两卷。先完成定位、人物、核心谜面、全书骨架和两卷目标，只细化近期前三章。本轮仅授权试写第1章，写完暂停复盘。请正式保存这次任务和范围；完成自检、登记与检查后，告诉我作品完整路径、正文位置、已登记范围、未登记稿和下一步。不要自动写第2章。

这是发给Codex的创作任务，不是终端命令。想先讨论，可把“试写第1章”改为“只讨论规划，不写正文”。远期允许保留骨架，无需先写完十二章细纲；初始化说明文件存在，不代表规划已完成。

本轮写到哪章、何时暂停等临时范围，应由Codex保存到正式任务状态和本地交接；不要写进作品定位、文风或权威世界规则。长期设定只放稳定的故事约束，避免下次续写时还读到“只许写第1章”的旧任务。

若尚未确认环境，可先在主项目终端执行：

```powershell
node bin/ai-writer.mjs doctor
```

`ok: true`表示工具文件检查正常，不表示文学质量通过。首次使用不用填写JSON、哈希、schema或修订令牌，Codex会依据你的实际指令准备必要输入。

## 2. 看交付，再决定下一步

每次结束应收到：作品完整路径、实际正文路径、已登记范围、实际审查范围、未登记稿或阻断，以及当前允许的下一步。先读正文；“文件已写”“已登记”“已审查”“作者定稿”是不同状态。

看完第一章后，继续在同一会话或新会话说：

> 恢复作品 works/雨夜来信，先核对当前任务、已登记章数、未登记稿和待回收线索。本轮授权写第2章，完成后暂停；不要覆盖已有正文，不把约定当作已发生事实。

也可以只恢复而不续写：

> 恢复作品 works/雨夜来信，只报告当前阶段、允许范围、作者已选与未决项、活跃修订和下一步；这轮不新增正文。

暂停规划可以说：

> 暂停正文，先讨论全书总纲并保存这次任务。投递员的身份已经确定，寄件动机仍待讨论；请分别记录已选和未决内容，下一会话不要自动续写。

保留整个作品目录，包括隐藏的`.writer/`和`.agents/`。只复制正文不能完整恢复状态。长篇后续按[从规划到导出的完整路径](long-form.md)走，跨会话只凭文件恢复，不依赖聊天记忆。

## 3. 审查、修订和导出

遇到局部问题可以直接说明，不必知道技能名称：

> 这部小说想写长篇，先检查已有点子能否持续产生不同选择与后果，明确本卷能兑现什么。保留我的题材方向，只滚动细化近期三章，这轮不写正文。

> 只审查第2章结尾和第3章开头是否接得住，核时间地点、人物伤情和知情，不为追读强加危机；给具体问题与应保留项，暂不修改。

Codex从doctor返回的`skill_root`按需读取`writer-novel/references/story-development.md`（长篇方向）与`writer-novel/references/scene-connections.md`（局部诊断）。已有作品更新后仍保留根作者定制，新参考应从当前包读取，不能假定根技能目录已有新文件；其他文体继续使用自身规则。

只审查：

> 完整阅读这两章，检查连续性、重复解释与人物口气，只报告具体问题和应保留的表达，不修改正文。

授权修改已登记章节：

> 在独立修订区润色第1章，保留情节、事实和人物声音；先核对需要重登的后续范围，如超出这次授权则先报告。完成实际修改、后续追踪复核和提交，保留原稿与改前改后对照。

旧章修改可能影响后续登记；“只改第1章”不自动授权改写所有后续情节。让Codex说明影响并使用已有授权，不直接改主稿或补哈希。去味方法见[去AI味流程](deslop.md)，意见处置见[复核手册](review-and-registration.md)。

导出：

> 导出 works/雨夜来信 当前已登记草稿到作品目录外的新目录，核对未登记稿、回退留稿与审查覆盖，说明纳入和排除范围，不覆盖旧版本。

结果为`manuscript.md`和`manifest.json`；检查清单中的范围、排除项和警告。导出仍是草稿，不自动上传或发布。

## 其他文体与独立目录

| 任务 | 如何说明 |
| --- | --- |
| 剧本 | 创建screenplay作品，说明短片/剧集、预计时长，先梗概和场次规划，仅写指定场次；动作可表演 |
| 历史散文 | 创建history作品，提供明确历史主题，先核验史料和事实卡，再写指定篇；不编造对白、心理和现场 |
| 散文/非虚构 | 创建essay作品，提供真实经历或素材，说明声音与篇幅，区分事实、记忆和观点 |

历史小说属于novel，非虚构历史才是history。不要将小说的谜面、强压或章末门槛套给所有文体。

新作品自带轻量工具、技能和手册。直接打开作品目录时，在该目录终端运行：

```powershell
node .writer/tool/bin/ai-writer.mjs doctor
node .writer/tool/bin/ai-writer.mjs status
```

主项目用`node bin/ai-writer.mjs`并传`--project "作品完整路径"`；独立作品用上述随附入口，当前目录含`writer.json`时可省略`--project`。更新后以该入口`--help`显示的包内手册为准，作品根手册可能保留作者笔记。

更新也会保留作品根技能。新会话按根作者规则恢复，并从help列出的“当前工具流程技能”读取新版流程；doctor的`skill_root`给出本次校验的技能目录，`project_skill_root`是保留的作者技能目录。包内说明用于补齐当前命令和保护流程，不自动替换作者定制。

长篇的context可能超过Codex单次显示容量。可让Codex用`--out .writer/drafts/context-本次.json`保存新入口，检查预算和`omitted_ids`，再分段核读所需内容；该选项仍会返回完整JSON，不会自动缩短控制台输出。看到“输出截断”应保留原输出、补读未显示部分；声称完整读过的正文和必读来源必须实际读全，不能仅凭文件已保存认定读完。细节见[使用手册](user-guide.md)中的“长篇上下文”。

若Codex在嵌套作品目录出现`helper_unknown_error`，返回主项目会话并明确作品完整路径；不要重新初始化或修改全局安全设置。已有作品导入、版本变化、修订恢复和工具升级分别见[使用手册](user-guide.md)、[版本与修订](revision-and-sources.md)及[本地安全更新](tool-updates.md)。
