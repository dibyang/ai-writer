# 快速入门：在 Codex 中开始写作

准备好能正常使用的 Codex 和 Node.js 20 或以上。不需要安装 npm 依赖。模型由当前 Codex 会话提供。

## 1. 打开主项目，检查环境

在 Codex 打开 ai-writer 项目目录。在终端运行一次：

```powershell
node bin/ai-writer.mjs doctor
```

看到 `ok: true` 表示文件与工具检查正常，不代表作品已经通过文学审查。

## 2. 直接说要写什么

将下面的作品名、题材和要求换成自己的，发给 Codex：

> 创建小说 works/雨夜来信，面向普通读者，计划十二章。启用长篇分卷，先完成定位、人物、核心谜面和故事骨架，再细化前三章。本轮仅授权试写第1章，写完暂停复盘。请把我的任务和范围正式登记，语言自然，不提前揭底；完成自检、登记和检查后，告诉我正文位置与下一步。

剧本可以说：

> 创建 screenplay 作品 works/最后一班车，写一部十五分钟短片。先完成梗概、人物和场次规划，再写前两场。动作可表演，各人物说话有区别。完成登记和检查。

历史散文可以说：

> 创建 history 作品 works/城与河，主题是我指定的历史事件。先阅读核验史料、建立事实卡，区分记载与推断，再写第一篇。不要编造对白、心理或现场细节，完成登记和检查。

历史小说选择 novel；讨论真实历史的非虚构选择 history。散文和一般非虚构选择 essay，并提供真实经历或素材。

0.5.0 新作品默认 schema 4，记录阶段、任务和有限范围，使用 changes 差量追踪，并支持设定版本和独立修订区。初始只允许讨论/规划；Codex 据你的真实指令保存原话来源并用 workflow set 登记。你无需填写 JSON，也不必重复确认已授权细节。工具不会仅因目录或大纲文件存在就自动认为已获正文授权。

## 3. 看结果，继续写

作品在 `works/作品名/`。正文在 `正文/`，下一步和未登记稿可让 Codex 查看：

> 恢复 works/雨夜来信 的当前任务、允许范围、作者选择和待登记正文。本轮授权写第2章，请据这条指令更新范围；按文件恢复人物所知和未收线索，完成后暂停并更新追踪。

换会话也可以使用同一句话。保留整个作品目录，包括隐藏的 `.writer/` 和 `.agents/`；只保留正文无法完整恢复追踪。

暂停写作可直接说：

> 暂停正文，先讨论全书总纲。保存这次任务，下一会话也只讨论，不写下一章。青岚宗方向和炼器先行已选；首件法器仍未定，小盾仅为推荐，请逐项登记，不采纳附带数字。

此时 status.next_unit 仍显示登记顺序，next.action 应指向总纲。context --purpose discussion 无需下一章细纲；decision current 区分已确认与候选。试写范围结束后先复盘，不默认无限续写。

跨卷或改过旧章后，可以说：

> 从当前文件恢复这部作品，回读将要回收的伏笔及最近变化，核对每个人实际知道什么、原物由谁保管。若旧章已修改，先处理后续受影响的知识和追踪，再续写；不要把约定当作已经发生。完成登记和当前版本的审查报告。

收到正文或资料改变的提示时，让 Codex 核对共同影响。schema 4 先建立独立修订区，在区内回退、逐章重读改稿和登记，完整尾段复核后 prepare/commit；主稿保留到事务提交，不直接编辑主稿后补哈希。

未来补设定可以说：

> 固定前六章真正使用的旧规则，实读新规则与相关正文。若只影响未来，从第七章发布；存在历史矛盾就建立影响待办和独立修订，不把“未来生效”当作无影响证明。

跨会话修订可说：

> 先 revision list，用本地交接的修订 ID 和令牌恢复原分支。核对主稿是否变化；如有冲突，保留双方候选，按新基线重新组织，不自动覆盖或刷新旧基线。

具体恢复、令牌移交及中断处理见 [设定版本与修订](revision-and-sources.md)。

详细步骤见 [长篇用法](long-form.md)。

## 4. 审查或直接润色

只想先看问题：

> 审查这两章的 AI 味，只报告问题。逐处区分模板表达、情绪空转、对白趋同与过度解释，同时列出应保留的声音和有效修辞。

已决定修改：

> 对这两章去 AI 味并直接润色，保留情节、事实、人物口气与有效修辞。先保存原稿，按实际阅读代价定点修改，给出改前改后对照，并处理回退、重新登记和后续影响。

详见 [去 AI 味用法](deslop.md)。

## 5. 导出完整草稿

> 导出 works/雨夜来信 的当前已登记草稿。先核对未登记正文、回退留稿和审查覆盖，说明哪些纳入、哪些排除。输出到一个新的导出目录，不覆盖旧版本。

导出包含 `manuscript.md` 和 `manifest.json`。先看排除清单，确认没有漏掉要交付的稿件。导出仍是草稿。

## 独立作品的入口

初始化会把技能、轻量工具和本套手册复制进作品。可以直接在 Codex 打开作品目录；在该目录的终端运行：

```powershell
node .writer/tool/bin/ai-writer.mjs doctor
node .writer/tool/bin/ai-writer.mjs status
```

只有当前目录包含 `writer.json` 时才能省略 `--project`。其他位置须传作品完整路径。

只读识别构建可用 `node bin/ai-writer.mjs tool identify`；比较随附工具用 `node bin/ai-writer.mjs tool compare --project "作品路径" --other "主项目路径"`。版本号相同不一定内容相同。这些命令不会升级工具。

旧 schema 1/2/3 继续按原协议运行。需要新保护时先只读预览；1/2 显式 governance migrate 至 3，再 protection enable 至 4，必须有对应作品授权和备份。schema 4 被旧 0.4 拒绝；本批无随附工具安全更新，使用新主项目入口，不能只复制 CLI 或手改版本号。先在独立副本验证，不自动迁移实际旧作。

在本机 Windows 的既有验证中，Codex CLI 使用嵌套作品目录作为 cwd 曾出现 `helper_unknown_error`，而从主项目目录启动并明确指定作品路径可以完成任务。遇到这类错误，返回 ai-writer 主项目会话，提供作品当前完整路径后继续；不要把宿主启动失败当成正文损坏，也不要为此关闭全局安全设置。独立 Node 工具可作为状态诊断入口。

更多任务见 [使用手册](user-guide.md)，具体参数见 [命令说明](workflow.md)。
