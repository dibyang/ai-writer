# 已登记正文按卷重定位：实施设计

2026-10-27。状态：0.10.0 开发实现；实际验收范围和失败记录见 `acceptance/20261027-relocation-0100-ai/`。与已提交的任务恢复视图分开管理；本轮不提交、不推送。本文不是迁移真实作品或发布新制品的授权。

## 背景与目标

两个真实使用场景分别需要把 36 章和 47 章已登记正文移入明确的卷目录，并让后续章节沿用稳定卷目录。维护工作区仅实现产品能力并使用合成作品验证；真实作品由原会话接管固定制品后操作。

目标是明确映射、逐字节不变、登记唯一、历史证据可解释、中断可恢复。不是改写正文、改变卷界、补写下一章或重新进行文学审查。

## 现状与核心约束

- `lib/revisions.mjs` 的普通修订要求旧章保留相对路径，不能用普通修订变相搬运。
- `lib/workspace.mjs` 的漂移、导出、登记模板与已有稿采纳凭据直接使用 `unit.draft`。仅移动文件或改一个 state 字段会破坏这些保护。
- `lib/sources.mjs` 的历史消费没有版本绑定时按原路径读取。旧 `source_hashes` 必须保留，不能批量替换后刷新原哈希。
- `lib/longform.mjs` 和 `lib/review-workflow.mjs` 的审查覆盖绑定正文路径、内容和依赖；纯移动不能冒充新的审读，也不能无理由丢掉有效审查。
- `lib/journal.mjs` 保存不可变快照差量；迁移不能改写旧差量或旧快照中的证据文本。
- `lib/tool-update.mjs:104` 的既有更新流程复制作品内容到验证副本，不能用于明确禁止复制旧正文的现场。
- 源状态为 schema 6，随附工具为正式 0.9.0；开发主线为 0.10.0。不能把修改后的窄制品标成未经修改的正式 0.9.0，也不能借迁移静默安装整批无关功能。

## 接口设计

| 接口 | 输入与结果 |
| --- | --- |
| `draft relocate-plan` | 显式逐章映射和稳定目录契约；只读返回完整基线、冲突、文件哈希和预览指纹 |
| `draft relocate` | expected_revision、generation、源/目标 build ID、operation_id、预览指纹、作者原话依据；执行受保护移动 |
| `draft relocations` | 只读列出进行中事务、已完成迁移与恢复入口 |
| `draft relocate-recover` | transaction_id、方向、锁指纹、作者依据；继续或回滚，不猜测所有者 |

上述接口已接入 CLI。输入拒绝未知字段。预览不写状态，不自动创建目标目录。正式执行重新核对预览全部前提，包括安装构建和实际执行入口构建。

## 数据结构与历史解析

新事件记录 operation_id、前后状态哈希、原构建与目标构建、作者依据引用、每章 unit/from/to/sha256/bytes、稳定卷 ID 与目录、前后修订号。历史 `source_hashes`、journal、冻结输入和审查原文保持原字节。

必须引入专门的正文路径解析层：当前正文地址与历史登记地址分离，用已验证迁移事件解释两者关系。解析限定正文、登记单元和指定内容版本；不能把通用 `safe()` 改成隐式别名器，否则写入和安全检查也会悄悄重定向。迁移链禁止环、同名歧义和跨单元别名。

迁移后修订正文时，旧来源仍按旧哈希核对，不能因为路径映射存在就跳过内容变化。旧审查只有内容及原依赖均相同才保持覆盖；显示技术路径等价，不生成新的文学审查时间或结论。

迁移显式启用 schema 7，老工具拒绝误操作；新建作品仍默认 schema 6。制品通过 `aiWriter.draftRelocationProtocol: 1` 声明所需模块及 schema 7 支持，不反向要求旧版具有新模块。

## 事务状态机与时序

实现状态为 `prepared → applying → completed`；检测到第三方冲突进入 `conflicted`，明确恢复方向后继续。回滚终态为 `rolled-back`，终态重复请求幂等返回，反向撤销必须新事务。

1. 取独占锁，检查无修订候选、无待影响、无中断事务、无正文或消费漂移。
2. 验证状态/CAS/generation/build、完整映射、作者证据与预览指纹。
3. 固定元数据基线和事务清单，再执行逐章移动；每步之前检查源与目标当前文件身份及哈希。
4. 重新核对正文、依赖、映射与文件数量，最后发布新状态。
5. 保留元数据证据和恢复记录，解除事务保护。任何阶段中断后，普通写入都必须被阻断。

正文不另存备份。实现用同卷独占 `link` 创建目标目录项、核对同 inode/字节后 `unlink` 原目录项，避免普通 rename 覆盖检查后突然出现的目标。正文数据只有一个实例；中断可能留下两条指向同一实例的路径，恢复只认可本事务映射中同 inode、同字节且恰好两个链接的组合。输入已有的外部硬链接仍拒绝，完成后只剩一个链接。文件系统不支持时拒绝，不退化为复制。元数据和工具可备份；不复用把旧/新正文复制成 `.bin` 的发布器。

## 路径、异常、幂等与回滚

源必须是唯一登记的普通文件；拒绝 symlink、junction、hardlink、路径穿越、Windows 保留名、尾点/空格、大小写别名、超长路径、重名目标、目标覆盖和跨卷错配。检查现存父目录的实际大小写及文件身份，不能只比较 JSON 字符串。

同 operation_id 同输入可重放；不同输入返回冲突。恢复逐条判断源/暂存/目标与期望哈希，第三方修改不覆盖、不删除、不自动抢锁。正文遗失或产生两个不同候选时保留现场，返回明确冲突。回滚恢复路径和元数据，不重写正文。

## 稳定卷目录

目录契约显式绑定稳定卷 ID 与目录，记录作者选定的范围；不根据滚动操作切片标题新建卷目录，也不因卷名修改而自动搬文。新章节只有落在已确认契约内才沿用目录，范围外需要新契约。目录不是剧情卷界的权威。

## 兼容性与无正文复制的采用流程

迁移实现和工具采用分别验证。普通 `tool update` 默认仍需要作品验证副本；新增显式 `validation_mode: "in-place-readonly"`，仅备份工具与元数据，以原位置只读校验作为采用门禁，校验期间持写锁；失败可恢复旧工具，不复制正文。采用 schema 7 后拒绝降级到不支持该协议的包。

先在隔离官方 0.9.0 基线上验证兼容协议，再确定窄候选制品版本和 content ID；不得冒充原正式包。主线 0.10.0 可以吸收同一实现，但真实作品是否采用主线不能替作者决定。

## 验收方案

使用合成 36/47 章作品，覆盖增量账本、正文消费来源、已有稿采纳、滚动审查和意见闭环。迁移前后检查逐章 SHA、字节数、合稿顺序、唯一登记、全部不可变证据字节、无未登记正文/漂移/待影响/活跃事务。

逐个移动边界、状态发布前后注入中断，分别 complete/rollback；覆盖目标存在、过期 CAS、坏哈希、错误卷、第三方改动、硬链接及 Windows 大小写冲突。拒绝时验证状态与非事务文件不变。

再跑跨会话恢复、历史上下文、旧章修订重登、审查覆盖、草稿导出与下一章稳定目录。最终固定制品解压后重复完整流程、`npm test` 与 `npm run doctor`。只使用合成书稿，不复制或写入真实作品。

## 风险与分阶段实施

高风险点是历史证据地址解析、老工具绕过新保护、中断期间的唯一文件实例、以及更新流程复制正文。四者任一未验收，都不能交付真实迁移。

1. 设计阶段：明确解析和协议保护，形成预览接口与只读负例。
2. 实现阶段：移动事务、恢复和历史消费兼容；稳定卷目录契约。
3. 采用阶段：无正文复制的受控工具采用与回滚，独立验证官方 0.9.0 来源。
4. 验收阶段：完整规模样本、最终制品与完整命令记录；交回原作品会话，不由维护会话操作真实作品。

当前实现与验收记录单独归入 AI 轮次；任务视图的 AH 验收不能作为本能力的验收。真实作品迁移、对外发布和采用整批 0.10.0 均不在本轮执行范围。
