# 0.10.0 起点：当前不足与下一步建议

更新于 2026-10-27。0.9.0 已发布；0.10.0 已增加开发版本接续和只读任务视图，尚未发布。以下其余建议不代表已经实施或承诺发布日期。

## 已有基础

八项创作治理的已确认范围均已实现。0.9.0 已覆盖分卷正文目录、长章分段、预算诊断、版本来源、保护修订和意见闭环，最终提交与标签的六组跨平台 CI 通过。候选实跑覆盖 66 章约 65.4 万汉字，以及实际跨会话恢复和旧章修订；这不代表任意规模重写或文学质量保证。见[发布验收](release-090-verification.md)。

## 当前不足

| 范围 | 现有证据与限制 | 建议方向 |
| --- | --- | --- |
| 任务易用性 | 底层模板和预览已减负，但正式修订仍跨多个命令、CAS、报告和登记步骤。长篇最终复核曾需重登 18–66 共49章、214次产品调用；实跑仍出现字段或顺序错误。该数字描述该场景，不是普通写章的平均成本。 | 由工具给出一个当前任务入口，集中展示下一步、缺项、阻塞和恢复点；复用现有命令执行及保护。 |
| 语义连续性 | 哈希只能确认版本。全书实读仍发现说话人、方位、人物知情、时间和数量误读；来源影响范围是保守判断。 | 由模型提出带原句的影响清单；工具绑定来源和确认状态，不能自动裁决或跳过复读。 |
| 语言质量 | 已有16例对照和8组段落改写恢复验证；不能外推检出率。长文仍有过度解释、相似动作和章尾、角色声音趋同的风险。 | 扩大带上下文与反例的复核集，分别记录漏检、误伤和无净收益；保持作者文风。 |
| 维护与发布 | 本次累计原始验收约7.89 GB；整体推送被拒绝后采用独立公开提交链。历史源码还有Windows保留路径；公开说明部分仍链接仅本地保留的记录。 | 将产品源码、公开摘要、私有原始证据分开存放；增加发布范围预检和文档链接检查。迁移旧历史另行设计，不改封存证据。 |
| 已知功能边界 | 限章候选续写只支持明确单章，不提供候选发布/自动合并；未承诺跨机共享盘、真实断电持久性、作者身份认证和自动联网升级。 | 按真实使用需求扩展，不把范围收敛重新称为八项未实现。 |

## 最优先：新用户任务引导与中断恢复

最小首批已实现 `status --view task`：从权威状态即时派生恢复位置和下一步，区分主稿/候选、授权、未登记稿提示、旧章重登、已结束候选与中断事务。默认状态提供入口；本批不自动执行多步操作、不判断分段完整性、不另存任务状态。验证记录在维护者本地 `acceptance/20261027-task-view-0100-ah/`；减少30%填写或纠错负担仍是后续待测目标，不因增加视图而宣称达成。

建议第一批只覆盖“恢复作品 → 续写一章”及“修订一处旧章 → 重登受影响尾段”两条主路径。基于当前 status/context/record-preview/revision 能力生成只读任务视图，列出当前阶段与授权、原稿和候选身份、未完成分段、待核内容以及准确的下一步。

执行时复用现有锁、CAS、源哈希和作者证据；机械字段可以自动填入，正文、事实判断、作者决定和审查采用必须保持真实依据。中断后恢复同一个任务，不创建重复稿、不刷新旧基线，也不把建议当作正文授权。先做现有状态到任务视图的最小闭环，再决定是否需要新持久状态；避免增加另一套权威账本。

建议验收：在隔离作品比较当前版与改进版的两个主路径，加上暂停拒绝、旧输入失效及修订中断恢复三个异常场景。记录人工JSON字段数量、产品调用次数、纠错次数、恢复耗时和最终文件状态；先取得基线，再以人工填写或纠错负担降低至少30%作为目标，未测量前不承诺达成。全部现有保护回归必须保持通过。

随后优先处理证据与发布的存放边界；上下文压缩、任意分支合并和更大章数验证需有具体问题与量化目标后再立项。本批不修改现有作品，其余建议另行实施。
