## 实跑发现的工具问题与实现

1. **独立修订区doctor资源定位错误。** 修订副本按设计不复制.writer/tool，原doctor直接访问该目录出现ENOENT。现在通过有效修订标记定位父作品安装包，诊断返回project_root、resource_project_root和revision_context；仍核验当前执行守卫与会话绑定，错版本明确拒绝，不重绑状态。测试覆盖健康只读、父包损坏及绑定不匹配；实际新修订区诊断通过。旧D绑定0.7.0被新运行时拒绝属于正确保护，原失败与前后状态哈希保留。
2. **完整长篇审查被20,000字符默认值拒绝。** D实际详细59章报告25,777字符，旧0.7.2拒绝。为完成当时已绑定事务，同样59章提供14,769字符精简版；详细原件保留。等该会话退出后再修改0.7.3，仅普通审查报告与重登审查报告使用现有1MiB文件上限；UTF-8实际字节保护、非空、范围、来源、哈希、冻结和当前性检查继续执行，其他普通字段20,000字符限制不变。最终版成功以原SHA登记完整D报告，并实跑28,438字符/64,327字节的106章长报告重登预览与登记。
3. **Windows测试目录清理偶发EPERM。** 首次全量测试在清理钩子失败；测试清理改为异步有限重试并验证目标始终在.tmp下。失败原件与后续全量通过分别保留，不合并成一次全绿。

修改位置为lib/workspace.mjs、lib/longform.mjs及相关测试；同步0.7.3版本、快速入门、使用手册和修订说明。未修改内置质量引擎。容量修复详细边界见[实现记录](report-capacity-fix/IMPLEMENTATION.md)。
