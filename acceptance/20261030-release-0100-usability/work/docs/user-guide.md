# ai-writer 使用手册

ai-writer 通过 Codex 阅读、写作和审修；本地工具负责文件、追踪、来源和导出。日常使用可以直接说任务，无需手工编辑追踪 JSON。

首次使用按 [快速入门](quickstart.md)。命令使用者另看 [命令说明](workflow.md)。

## 任务入口

| 我想做什么 | 可以直接告诉 Codex | 主要结果 |
| --- | --- | --- |
| 新建作品 | 创建作品到明确目录，说明文体、题材、篇幅、读者和文风；先规划再写指定范围 | 设定、大纲、正文和追踪 |
| 接着写 | 恢复指定作品状态，先核对待登记正文，再写下一章/场/篇 | 新正文及更新后的追踪 |
| 写长篇 | 启用长篇追踪，建立分卷契约，按近期细纲连续写到指定单元 | 分卷、增量追踪、线索和滚动审查 |
| 带旧稿继续写 | 从指定的自有分章文件建立新作品，先登记旧稿基线，再续写 | 冻结原稿、阅读覆盖、断点进度 |
| 只审查 | 审查指定范围，报告实际原句与阅读代价，先不改正文 | 带范围和哈希的报告 |
| 修改旧章 | 授权润色指定章节，保留哪些内容；处理回退与后续受影响追踪 | 修订稿、原稿备份及重新登记 |
| 去 AI 味 | 按本书声音定点去味，保留事实和剧情，给改前改后对照 | 专项诊断、修订及复核报告 |
| 导出 | 核对未登记稿与审查覆盖，导出当前完整的已登记范围 | 合并草稿、范围与排除清单 |

提供明确作品路径，避免并行作品混用。题材、人物、结论等核心选择以作者要求为准；普通创作细节可授权 Codex 自行处理。

## 如何理解“已完成”

- 文件保存在 `正文/`：文本存在，但不代表追踪已登记。
- 已登记：正文、细纲和已读来源的哈希绑定到当前状态，可用于后续创作。
- 已审查：报告说明实际阅读范围与版本。脚本的 check 只做机械检查。
- 已导出：清单列出的已登记正文已合并。查看 `excluded_drafts`，确认没有遗漏本次需要交付的文件。
- 作者定稿：由作者决定；工具不会把前面几种状态自动升级为定稿或发布。

`status` 的 `draft_inventory.unregistered` 列出未登记的正文候选，可能是新稿、替代版本、回退保留稿或放在正文目录中的归档。不能直接自动删除或合并。让 Codex 实读、核对用途后处理。归档建议放在作品的独立归档目录，保留来源说明。

## 新会话恢复与长篇

恢复顺序是查看状态、处理来源漂移或待登记稿、读取当前章纲和相关原文，再继续写。聊天中的旧描述不能替代作品文件。

长篇需要显式启用，之后使用 `changes` 增量登记；短篇兼容流程使用完整 `snapshot`。Codex 会按作品状态选择格式，不要把两种模板混用。分卷、角色知情、物证交接、旧线索回查和每三单元滚动审查见 [长篇流程](long-form.md)。

“待核”“未回收”不等于漏洞。记录已知边界和下一步，不为让清单好看而提前结案。检索只帮助定位，回收早期线索仍须回读原文。

## 旧稿导入与换位置

当前支持明确排序的 UTF-8 Markdown/TXT 分章文件。合订本先另存拆章副本，保留原文与位置映射；不要覆盖原稿。导入新建空作品，冻结原文，逐章实读和登记。未读的范围不能宣称已分析。

原文件移动后：

1. 查看 `import-status` 的 `can_continue`、`blockers` 与具体路径。
2. 如果只是换目录，准备 unit/path 映射，使用 `import-relink`。工具要求新位置的内容与冻结副本哈希完全相同。
3. 再查看状态并继续导入。重定位单独记历史，不改正文、冻结清单或已登记来源。

自然语言示例：

> 这部作品的旧稿移到了 D:/我的小说/原稿。先检查导入状态，按章节核对新位置与冻结副本是否完全一致；一致的用正式重定位命令恢复，不手改状态或来源清单。有内容不同的单独报告。

如果内容也变了，这是版本变更，应明确选择基线与修订方案，不能当作换路径。具体 JSON 见 [命令说明](workflow.md)。

## 修订和去 AI 味

明确希望“只报告”还是“直接润色”。修改已登记章节前，先保存原正文、查看修订号，核实最早受影响范围，再通过 rewind 回退并逐单元重新核对登记。回退保留正文；旧审查报告的结论不自动适用于新稿。

去味流程见 [专项指南](deslop.md)。它关注可观察的阅读问题，不追求检测器分数。单个词、比喻、长句或议论不是自动错误；不同文体使用不同标准。

## 常见问题

| 看到的情况 | 下一步 |
| --- | --- |
| 没有细纲 / PLAN_REQUIRED | 让 Codex 先规划该单元，或用 plan --help 查看示例 |
| 目录里有正文，导出没包含 | 查看未登记列表，核对并完成登记；不要直接手改 state |
| 正文或资料已变化 | 先核对最早消费者，回退并重新读取、登记 |
| 不知道参数 | 使用 `命令 --help`，可获得用途、参数、输入示例和本地手册路径 |
| JSON 错误 | 按文件名与行列修正，双引号属性名、无尾逗号，UTF-8 保存 |
| 目标目录已存在 | 使用新目录；初始化和导出不会覆盖旧内容 |
| 原稿换目录 | 用 import-status 定位，再用 import-relink 核验同一内容 |
| Codex helper 启动失败 | 返回主项目会话，明确指定作品路径；独立 Node 工具可检查状态 |
| 存在写入锁 | 先确认没有活跃写作任务，保留现场再排查；不要自动抢锁 |
| 语言扫描没有命中 | 仍需完整阅读；语义问题不一定包含已知模式 |

## 保留与备份

保留整个作品目录，以及需要留存的外部原稿和导出目录。 `.writer/` 保存权威状态、差量记录和回退备份；`.agents/` 保存随作品使用的技能。原稿与审查报告建议按版本另存，不覆盖已经绑定哈希的材料。

0.3.0 新建作品自带本手册和新工具。既有作品不会自动更新随附工具；可以从当前 ai-writer 主项目显式传 `--project` 管理旧作品。替换旧作品随附工具前先备份、核对版本和完整模块，再运行 doctor；不要只复制一个 CLI 文件。

随作品保留的许可、来源清单与原文哈希见 [来源与许可](attribution.md)。历史来源清单不表示清单中所有主项目组件都已随作品复制。
