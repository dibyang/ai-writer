# ai-writer语言审查P1验收单

## 用途与当前事实

作者在反馈发送和两项P1推进消息后再次要求“继续推进”。此单把已提出的改进收束为交付核查项，不新增功能批次、作品改写或迁移授权。

本会话只读核对工具项目的`assessment.md`、`language-eval/root-semantic-review.md`及现有会话进度：反馈已收录；16例分类校准有实际结果且明确局限；66章当前正文实读覆盖已完成，但已知两处问题的正式修订、完整最终验收尚未结束。它们不能提前抵作本单两项P1的完成证据。

## P1-A：语言与事实判断分别执行

交付应指明使用的技能入口、规则版本或哈希及实际受测材料，不把开发目录新规则与旧固定包混称同一构建。

每个实读单元的记录应能分别回答：

- 阅读到哪个版本、什么范围；若分批或截断，缺口怎样补齐。
- 情节/连续性判断是什么，依据在哪里。
- 语言判断是什么，准确原句及邻段是什么；为什么会误解或重读，不能只写“有AI味”。
- 哪些是确定错误、需上下文核实的疑点、可选风格建议。
- 哪些正常表达保留，理由如何由语境支持。
- 问题来自作者校准、模型新发现还是修改后新发现，不能混记。

最低验收：在一个逻辑自洽但表达有问题的完整邻段中，不能因事实成立就省略语言判断；同时在正常省略、专业或正式语体、修辞正例中说明保留理由。按案例逐项判断，不以每章发现数、删字量或标签命中率代替质量。

## P1-B：最小修改与改后复读闭环

实际运行必须包含以下连续环节，只有修改方向或建议清单不能算闭环：

1. 读原段，记录原文版本、诊断和拟保留事实。
2. 在独立验证材料和明确授权范围内实际修改，保存最小差异。
3. 完整回读修改句及前后邻段；若影响跨章时点或物件归属，读必要的相关段。
4. 分别核对意思、语气和新歧义，必要时再改、再读，保留失败过程。
5. 对齐最终材料、结论、引文和版本；需正式登记的作品使用正常保护入口，不追认旧报告。

核查要点：谁做什么；动词作用于什么；“方才/前次/再来”等比较时点；气料、灵气、练量、时间和金钱等耗用对象；物件持有人；说话人实际所知与未出口内心。没有相关项时说明不适用，不强行造齐全部错误。

最低验收组合：一组实际错误的保义修改、一组应保留表达、多身份口气，以及至少一种修改后反而引入新歧义的对照。最后一类必须说明为什么新改法不合格，最终怎样修正或退回，而不是只声称“已检查改法”。

## 防止验收失真

受测者不读取预期判据、其他模型答案或上一版输出；控制者可读判据以复核，但须说明材料与判据的设计关系。同一维护方设计的样本不能称独立未知集；新设计变体也不自动等于真实读者检验。引文、哈希、范围与流程可做机械校验，文学自然度仍靠具体语境判断。

当前冻结v5及其测试记录保留。若P1需要修改规则，另立候选并核对最终交付内容，不能倒用旧包结果。优先复用已有报告字段与技能示例；只有证明现有格式不足再讨论扩展，本单不授权schema迁移或自动评分。

真实《带着科学去修仙》只读，不动正文、来源、登记和随附工具，不写36章；不提交推送、不上传正文。此单仅是验收要求，不是完成报告。
