# ai-writer 0.9.0（开发中，未发布）

下一版本为0.9.0，本页为开发中的发行说明。当前正式下载仍是[v0.8.0](https://github.com/dibyang/ai-writer/releases/tag/v0.8.0)，尚未创建或发布v0.9.0。

打包工具补充Git来源读取的临时中断恢复与具体错误提示：最多重试一次，仍失败就停止，保留诊断和失败暂存，不将不可靠信息当来源记录。

ai-writer是面向Codex的中文创作工具，支持小说、剧本、历史散文、散文与一般非虚构。0.9.0在已有长篇、修订与审查能力上增加上下文预算超限诊断、按需长章分段合成、纲文实读回对和关键选择的短程推演；来源核查与取舍保留在源码仓库。工具不自动截断必要上下文，文学判断仍需模型实读和作者确认。

后续流程实跑修复了显式扩容后的大上下文仍被内部登记预算阻断的问题，并补充未完成长章的交接和恢复指引；文件容量、完整来源及授权核验继续保留。具体修复前后证据及实际范围见源码仓库Q轮记录。

扩规模流程进一步补充正式修订后的中间稿管理：分段和普通交接不会随修订事务自动同步，恢复时以当前完整正文为准，另存并核对新分段版本，保留旧入口为历史。实际验证进度及范围见源码仓库S轮记录。

登记预览增加按角色关联的未变条目候选，最多8条并标明遗漏数，帮助实读者发现其他线索中的知情漏更新。它不自动理解文字、判错或补账本；来源、修订号和不可变观察保护继续生效。

重登草案改为恢复原登记真正变化的字段和逐人知识差量，避免整张旧表覆盖前章修正；新条目、物证换手、来源绑定与实际尾段复核仍按原保护执行，不把结构差量当自动语义合并。

独立修订发布补充原观察的基线核验：即使回退到首次出现之前，重登也不能删除或改写既有观察的原字、类型及作者真相。中断后的继续发布同样核验，按原备份回滚仍可执行；知情更新和另建解释继续支持。

修复恢复未知命令错误时，帮助入口携带通用`--project`参数又失败的问题。`help`及单项帮助接受作品通用参数，保持只读，不依赖作品存在，也不忽略未知、重复或缺值参数。

独立修订区的`tool identify`改为复用经校验的父工具并显示修订上下文；会话绑定不符或父包损坏仍明确失败，不向候选复制工具或追认旧绑定。

新增`assemble`按有序分段及SHA256创建新完整稿，不覆盖、不登记；支持可选`draft_review`将已保存报告与本章绑定，正式登记冻结报告。账本状态错误提示列出准确字段及允许值。完整章仍须实际阅读、回对细纲并保存报告，失败后停止依赖步骤；文件保护不等于文学通过。CI增加macOS配置，配置存在不代表本轮已经在该平台执行通过。

## 安装与开始

本地构建命令为`npm run release:build -- --out dist/0.9.0`，生成开发候选`ai-writer-0.9.0.zip`和`SHA256SUMS.txt`，不等于正式发布。核对SHA-256后解压到新目录，在Codex中打开`ai-writer-0.9.0`；需要Node.js 20或更高版本，无须安装npm依赖。

```powershell
node bin/ai-writer.mjs doctor
```

然后说：“创建小说 works/雨夜来信，先规划两卷与近期前三章，本轮只试写第一章，写完暂停；完成审查、登记和检查。”详细流程见包内`docs/quickstart.md`和`docs/user-guide.md`。

## 已有作品与版本兼容

先备份，使用包内当前工具的`tool identify`、`tool compare`和`tool update-plan`核对，再按手册显式更新。不要覆盖现有作品目录，也不要只替换CLI。作品正文、作者规则和本地定制不因本次发行而自动改写。

0.9.0沿用schema6和受管资源协议，识别完整0.7、0.8及0.9包，保留`apache-2.0-v1`资源配置。版本号变化不自动迁移或更新已有作品；活跃修订结束后再单独规划更新。历史内部0.8.0和0.8.1候选保留原验证身份；不能仅凭版本号判断内容相同，应核对内容ID与差异计划。
