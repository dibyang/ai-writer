## UX-01 / P2：未登记正文缺少可见提示，导出容易漏掉最新内容

位置：`lib/workspace.mjs:294-329`、`lib/workspace.mjs:380-386`。

复现：登记第 1 章，再写入 `正文/0002-尚未登记.md`，但不登记。依次调用 status、check、export。

实际：status 仅显示 next_unit=2；check 返回 ok=true、findings=[]；export 成功并仅含第 1 章，未报告被排除的正文文件。回退后也存在同样的信息缺口：正文留在目录中，但状态只提示下一单元号。

影响：用户或接手会话难以一眼区分“已写且已登记”“已写但待登记”“回退后待重新核对”。可能把遗漏最新稿件的导出当作本次完整交付。导出清单确实列出包含单元，原稿也未丢失，但缺少主动提示。

建议：status/check 列出未被追踪引用的正文候选；export 返回包含范围、排除文件及原因。未登记文本仍不得自动合并，冲突稿和回退留稿由 Codex 实读后处理。

验收：同时覆盖新稿未登记、同编号不同文件名、回退残留稿、目录中有明确归档文件；结果说明哪些未导出，不擅自改变正文或状态。

证据 ID：`unregistered-status`、`unregistered-check`、`unregistered-export`、`rewound-status`、`rewound-check`。

## UX-02 / P2：入门和生成说明仍推荐本机曾失败的独立目录启动路径

位置：`README.md:22-26`、`lib/workspace.mjs:171`；限制说明在 `README.md:98`、`docs/long-form.md:13`。

实际：入门先让作者在 Codex 中打开新作品目录；生成的作品 README 也只有这个入口。当前机器此前以嵌套作品目录作为 Codex CLI cwd 时，status/doctor/check 启动前就遇到 helper 初始化错误。成功路径是从 ai-writer 根目录启动并明确指定作品路径。

影响：新用户优先接触推荐入口，遇错后才可能在验证说明或长篇文档末尾找到绕行办法。作品被单独拿走时，生成 README 不包含这个已知限制及恢复方法。

建议：在入门第一屏提供已验证的根目录操作方式；独立目录方式保留为可选，并就近写明本机限制和返回根目录的操作。生成 README 也应提供可执行的恢复提示。

验收：按文档原样启动一个新作品，验证首次写作和新会话续写；同时验证故障提示能把用户带回可工作的入口。

证据：[此前失败实跑](../20261015-long/novel-stage-b/final.md)、[此前成功重试](../20261015-long/novel-stage-b-retry/final.md)。本轮未重新触发宿主错误，不推断其他机器必然失败。

## UX-03 / P2：独立作品帮助指向不存在的使用文档

位置：`lib/workspace.mjs:197-200`、`lib/workspace.mjs:350`。

复现：初始化作品，在作品目录运行 `node .writer/tool/bin/ai-writer.mjs --help`。

实际：帮助提示去看 `docs/workflow.md`、`docs/long-form.md`；这两个文件都没有随作品复制。长篇技能参考文件存在，轻量工具 doctor 也正常。

影响：独立作品的命令使用者无法顺着帮助查看 JSON 格式。Codex 可以另读技能恢复操作，但作者的自助路径中断。

建议：随作品携带一份自足的使用指南，或让嵌入版帮助指向真实存在的技能参考，并补足基础命令、历史事实卡和常见错误示例。链接应按主项目与独立作品两种目录验证。

验收：将作品复制到主项目外，关闭主项目访问，仅凭生成 README 和帮助完成基础操作，不出现指向缺失文件的入口。

证据 ID：`embedded-help`、`embedded-doctor`；`results.observations.embeddedDocs`。

## UX-04 / P2：旧稿移动后状态与下一步不一致，缺少受保护的重定位入口

位置：`lib/longform.mjs:221-238`。

复现：import-index 冻结一个源文件，随后把测试源文件改名，冻结副本保持原样。执行 import-status 和 import-next。

实际：import-status 返回 ok=true、changed_copies=[]、changed_originals=[1]；import-next 随后退出 2，要求核实原文件变化或缺失。将原文件恢复到原路径后，import-next 成功。本轮核实冻结副本哈希始终一致。

影响：状态的成功信号不能直接代表可继续导入，且用户把旧稿整理到新目录或换机器后，没有文档化的安全重定位步骤。当前返回的信息不足以形成明确的下一步。

建议：保持源版本核验，补充 can_continue/blockers 和具体缺失路径；提供显式重定位流程，只有新路径内容哈希与冻结版本相同才可绑定，并保存来源变更记录。已被消费的来源清单变更须设计其依赖迁移，不指导用户手改 manifest 或 state 绕过校验。

验收：覆盖相同内容换路径、相同名字内容变化、部分章节移动、已登记部分章节后换机器；正确区分恢复路径和切换内容版本。

证据 ID：`relocated-import-status`、`relocated-import-next`、`restored-import-next`；`results.observations.frozenIntact`。

## UX-05 / P2：子命令帮助与常见错误缺少可直接执行的下一步

位置：`lib/workspace.mjs:353-369`、`lib/workspace.mjs:221-222`、`lib/workspace.mjs:37`。

复现：运行 `init --help`、`record --help`；在刚初始化且没有章纲的作品上运行 context；提交含尾逗号的 JSON。

实际：两个子命令帮助都报“无效、重复或缺值参数：--help”；缺章纲只返回 Node ENOENT；无效 JSON 返回解析位置，但没有输入文件名与修复示例。

影响：使用者无法在卡住的命令处求助，必须跳回总帮助或翻阅多个文档。Codex 通常能自行推导，但会增加试错调用，普通作者难以判断究竟缺什么。

建议：支持每个子命令的 --help；区分没有章纲、没有作品、无效输入、过期状态等错误，返回涉及文件、当前单元与下一条操作示例。缺章纲提示先 plan，空作品导出提示先完成登记；保留原始诊断供排障。

验收：子命令帮助退出 0；常见失败给出正确路径和最短恢复步骤；帮助不能绕过输入检查或改变数据。

证据 ID：`init-help`、`record-help`、`wrong-project`、`empty-context`、`empty-export`、`malformed-json`。

## UX-06 / P3：作者常用任务的入口不完整，去 AI 味能力尤其难以发现

位置：`README.md:7-26`、`docs/workflow.md`、`examples/prompts.md`、`.agents/skills/writer-review/SKILL.md`。

实际：文档已有入门和命令说明，但常用提示词未覆盖明确的“去 AI 味”、旧稿导入后续写、跨卷恢复、导出前核对全部待处理稿等任务。基础手册主要讲 snapshot 协议，长篇 changes 流程需要转入另一份技能参考；作者需要自己拼接多个入口。

影响：能力存在于内部规则，但用户不知道该怎么触发、会得到什么结果、审查和直接改写有什么区别。用户本轮对去 AI 味的追问就是一个实际的发现性信号，不能仅用“已有某条规则”证明入口已经好用。

建议：增加作者向的快速入门和任务索引。每项给可直接粘贴的自然语言、需要提供的资料、输出位置和完成标准；清楚区分“只审查”与“授权润色”。命令与 JSON 放在技术手册中，基础流程开头明确短篇/长篇协议选择。

验收：让未看过代码的使用者仅凭文档完成新建、恢复、局部修订、去味审查及完整导出；记录实际卡点，不用模型自评代替真人试用。

## 本轮正常的路径

- 中文且含空格的作品路径可以初始化、登记、检查和导出。
- 带 BOM 的 UTF-8 JSON 章纲可以读取，正文及输入中的中文正常。
- 写前模板带入真实修订号与来源哈希，顺序登记正常。
- 独立作品的 Node 轻量工具与技能可用，doctor 通过。
- 修订回退保留全部正文和状态备份，不靠删除正文解除保护。
- 原文件漂移会阻止导入下一章；恢复原路径和内容后可以继续。

这些是本轮实际观察，不扩大为跨系统、完整百章语义或作者验收。

## 已知设计代价，单列观察

在已登记两章后，仅向 `设定/文风.md` 追加“从下一章起减少重复解释”，也会使两章都列入 changed_sources，并阻断下一章 context，要求从最早消费者回退。`style-changed-status`、`style-changed-context` 已复现。

这是当前整文件依赖保护的既定行为，不是本轮新发现的校验缺陷。长篇使用成本较高。后续可设计带生效单元的规则版本，但必须区分从现在生效的文风选择与会影响旧剧情的事实修改，不能直接放宽哈希保护。
