# 验收记录器作品路径说明

B新会话入口三条只读调用漏--project，CLI按实际cwd在主项目根查找作品并退出2，没有执行正文/状态写入。v-log.mjs默认的project字段和state快照指向意图测试的W，它没有替CLI补参数，因此这些失败行不能被解读为“CLI已针对W正常运行”，原实际argv和原始诊断保留，不改旧日志或用补参成功覆盖失败。

后续可复用新验收专用v-writer.mjs：只给日志小写标签与产品命令/参数，它在实际argv中明确追加--project W，再交原v-log记录。独立修订区仍须显式--project返回workspace及--revision-token；默认主区在修订占用时仍由产品拒绝，不抢占/旁路。日志中的实际CLI argv与快照项目因此一致。

这只是V实跑工装的调用减负，不是产品新增“按工具路径自动猜作品”行为，不修改产品或重写已运行的v-log。包外工具更新及其他入口仍用v-log并显式传作品路径。普通作者继续通过Codex描述作品和任务，不需要使用这个验收脚本。
