# 百章长篇扩大实跑计划

基线：8c7aded，复制上一轮《潮汐信号》revision 67、24章作品到本目录，旧证据目录保持原样。

- 目标100章。原1–24章为上一轮1500–2000正文汉字的第一部；新增25–100章每章2400–3200正文汉字，Unicode Script=Han，去Markdown标题计数。分别报告旧章与新章，不能把平均值冒充每章达标。
- 13个独立创作进程，每次6章、末次4章；由作品文件恢复，不向下个进程传聊天情节。至少3次多处旧章修订，完成后用全新进程继续，核验新旧信息边界。
- 第1–24章已兑现的观察、主线结论、物证及人物知识仍有效；续部以新卷契约和新文件规划，不能因续篇需要把第一部改成未结案。
- 修订需求将在实际早期章节形成后，以具体原句和因果消费点设计，防止给不存在的情节写虚假测试。正式rewind、逐章重登，检查ID、旧证据、due、人物历史知识、前缀记录保留。
- 每3章滚动连读最近6章，相关早期证据回查；原生报告绑定实际哈希。主会话进行机械独立复核、关键修订与长线回收语义复核，明确实际阅读覆盖，不把脚本或哈希扫描当全文审稿。
- 原生request/events/stderr/final/process-result、阶段CLI原始输出、正文、状态、journal、来源、报告和导出留档。失败与重试使用新名称，最终证据清单按字节封存。
- 预计10–16小时，先以第25–30章耗时校正。按阶段反馈；未完成100章前不标完成。检查预算、退出异常和停写均保留断点。
- 不提交、不推送、不发布；原`.idea/`保持原状。最终修改工具须运行npm test、npm run doctor，若改内置引擎另跑test:engine；本轮即使未改引擎也保留原有回归。
