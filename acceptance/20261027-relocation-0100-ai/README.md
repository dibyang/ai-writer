## 实现

1. `draft relocate-plan` 只读检查显式映射、完整卷目录契约、路径唯一性、Windows 路径限制、现有链接与目标占用；输出状态/代次、安装构建、执行构建及预览指纹。
2. `draft relocate` 在原写锁内重验基线和作者证据，冻结不可变迁移事件，移动正文，最后发布 schema 7 状态。旧版工具拒绝操作 schema 7；新建作品仍默认 schema 6。
3. 旧正文消费哈希、journal、冻结输入和审查报告不改写。通过已验证事件解析历史地址，当前登记使用新地址；实际字节变化仍使历史消费和审查失效，不能靠别名追认变化。
4. 事务记录纳入随附工具文件及清单，检查安装记录与真实构建的一致性，防止手工替换后重建清单被追认。冻结清单时再次核对状态和工具哈希。
5. 独占创建目标目录项后撤去原目录项，正文数据不复制。短暂双路径必须是同 inode、同哈希、恰好两个链接的本次映射；完成后每章一个路径、一个链接。普通输入中的硬链接与符号链接仍拒绝。不支持安全同卷操作的文件系统直接报错，不退化为复制。
6. `draft relocations`、`draft relocate-recover` 复用原进程存活检查、锁指纹与作者恢复依据，支持中断 complete/rollback、幂等和冲突保留。普通读写在事务未结束时阻断，任务视图指向迁移恢复入口。
7. 稳定卷目录不随滚动卷纲标题变化；超出已确认目录范围时拒绝默认回退。已有 schema 7 作品可用空 mapping 显式扩展未来目录契约。
8. `tool update` 新增显式 `validation_mode: "in-place-readonly"`：原位置只读核验作品，只备份工具与元数据，不向验证目录复制正文；原有 copy 模式保留。

快速入门、使用手册、变更记录、发布说明和实施设计已更新。未修改内置引擎，因此没有以引擎测试替代本轮工具验收。

## 失败与修复

- 首轮定向测试中恢复被普通写保护拦住，修正为专用恢复通道，并复用原进程存活与锁指纹保护。`targeted-first.txt`、`targeted-second.txt` 保留。
- 第一轮全量测试及 47 章升级实跑暴露旧包识别问题：新增模块被反向要求出现在 0.7/0.8/0.9 包中。修复包识别、来源完整性检查和 doctor，依据包的显式迁移能力标记选择模块。升级失败停在预检，旧正文和状态保持，后续复用了同一合成基线。
- ai2 全量测试中，手册文件链接检查误把 Markdown 章节锚点当作文件名；修正链接检查器，保留有效的章节跳转。
- `review-apply-before-fix` 实际复现意见闭环按旧路径比较的漏点：已完成实际修复和二次迁移，但 apply 被拒绝，状态未改变。统一真实提交与当前登记的路径等价判断；正文 SHA、差量、依赖等其他字段仍严格核对。加入永久回归并重跑实际 CLI。
- 收尾复核补上安装构建匹配和事务期间工具文件保护。新增负例证明手改清单不能追认工具替换，中断期间第三方改动保留且拒绝恢复覆盖。
- 此负例第一次使用 `writeBuildManifest` 覆盖已有文件，被其正确的 `wx` 保护拒绝；调整合成篡改测试的准备步骤后重验通过。该错误是测试准备问题，没有放宽产品保护。
- 各项修正后重新构建最终 ai6 包，重新跑全量回归及全部规模场景；前几轮通过不替代最终包结果。

## 记录与重现

`capture.mjs` 为每个唯一标签保存输入原文、stdout/stderr、产品退出码、前后状态和运行模块指纹。以各目录 `result.json` 为准，不把外层 PowerShell 退出码当产品结果。故障注入预期的 90/92/93/94/95/96/97 等退出与普通拒绝分开看，不能把预期中断算成验收失败。

脚本 `scale-flow.mjs`、`scale-resume.mjs`、`post-migration-flow.mjs`、`review-chain-flow.mjs`、`review-apply-flow.mjs`、`copyfree-recovery-flow.mjs` 保存实跑步骤；每次运行需新标签及独立目录，禁止覆盖原证据。单元测试的临时 fixture 按既有测试框架自动清理，测试代码与日志保留；CLI 失败现场和成功场景均保留在 `scenario/`。

`verify-final.mjs` 检查最终命令结果、所有发行来源文件与解压载荷。`seal.json` 和 `seal-files.json` 是本目录最终证据清单，不包含它们自身；封存后不再改动已有记录。
