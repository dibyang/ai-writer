# 创作研究与拆解

先确定研究问题，读实际素材。用户给网址时读取原页；要最新榜单、市场变化或当前规则时联网核验并记日期。没有工具或访问受限就说明缺口，不能编造排行、热度、数据或阅读经历。

## 选题

按当前受众、平台、类型、篇幅和作者优势提炼候选方向。每个候选说明：读者需求、人物处境、冲突资源、差异点、长线供给与不适用情况。数据与判断分开；少量榜单观察不能预测商业成功。

## 拆文

从外到内：定位与承诺 → 开篇入口 → 结构与信息释放 → 人物目标及关系 → 情绪/节奏 → 表达机制。每条判断给实际章节或段落锚点，不只赞“节奏好、人设强”。

输出到 `参考拆解/主题.md`：来源与范围、关键观察、证据位置、机制、适用条件、迁移方式、失败风险。可迁移的是“延迟公开使关系承受压力”等功能，不是换名字复制案件、人物组合、反转和独特句子。只保存任务必要的短摘录，完整素材按合法来源与用户授权管理。

原作成功不证明某一方法单独有效。标明观察与推断，保留失败条件。对标材料可选，作者文风始终优先。

长篇拆解按连续章节块保存读取覆盖、原文哈希、观察和未确认项，再从落盘结果汇总；换会话先恢复这些记录，不把抽样或机械索引称为全文深读。原文变化后重核受影响块。区分客观事件顺序、读者获知顺序和人物获知顺序，不能用后文真相倒填前文人物认知。自有旧稿是续写基线，使用writer-project导入流程，不自动放入外部对标或跨书灵感库。

## 有资料时怎样借鉴局部机制

专项参考先回查相邻上下文，记录位置/哈希、它解决的具体问题、依赖条件，以及本作品可以独立实现的做法。需要对比时可选少量不同做法及失败例，数量不设硬门槛；没有合法可用的范例仍可原创。不要默认抓取或打包小说语料，不把自有稿混入跨书素材库。示例成功只支持机制观察，不证明市场效果。

## 历史与事实

已有本地资料优先查全文及上下文，再补版本、异文、页码和研究。史源有抄袭或传承依赖时登记，不能虚增互证。查到网页摘要不等于读过原文。历史事实卡按 writer-history 填写，未核不标 verified。
