# 通俗历史散文

作品文体为 history。先读取 [史料与讲述](references/history-method.md)，用 writer-project 管理文件。用户已有史料库时先检索本地原文与上下文；再按缺口查版本、影印与研究，不重复漫搜已有全文。

## 研究到正文

1. 确定章节问题、人物处境与事件时间线。把关键事实、责任判断、数字、直接引语及争议记载做成 `研究/主题.json` 事实卡，注明主出处、版本定位、原文、核验时间、互证及史源依赖、能够和不能够证明的边界。没有实际核查不得标 verified。
2. 每个 claim 区分 `direct` 直接史实、`inference` 常识性推断、`reconstruction` 非因果场景复原、`attribution` 关键归因。人物未载心理、精确动作、天气和私下对白不能当作直接史实。
3. 用人物面临的选择、已确认行动和结果组织细纲，并把事实卡列入 research_refs。工具验证字段，不会替作者判断史实真假。
4. 正文让普通读者一遍跟住人、事与因果；制度解释落到谁可以做什么、谁承受后果。事实边界有分寸，声音可以温暖、好奇、松弛或风趣，不统一压成冷静材料腔。
5. 合理推断不机械加“可能”；一旦增加具体个人未载经历、排他解释或责任结论，就按严格核证处理。若使用允许的非因果场景复原，正文可识别不确定性，章末说明依据和未确认部分，删去不影响因果。
6. 史源说明写真实书名、卷次、篇名及实际核过的版本页码。内部卡号、工作包、路径和“页码待补”等制作语言留在研究和报告，不进入读者正文。缺正式页码时不编造，可用已核卷篇定位，完整出版引注是否满足由作者另行裁定。
7. 自检分别判断事实、自然表达、易懂与追读、人物亲近、叙述者亲和、散文性、跨章声音；一项通过不能替代其他项。

史料不足时完成可做的研究和缺证表，不生成假定稿。作者明确要虚构演绎时，另建 novel 或 screenplay 作品并清楚标识。
