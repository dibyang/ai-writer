# D批：随附工具安全更新与最终整合

日期2026-10-18。基线257c08ad。本轮继续原设计D/AW-07；状态为实现候选，实际完成及未覆盖项以本批最终记录为准。不修改现有作品、不联网升级、不自动提交或推送；验收仅另建作品或原封存的必要文件副本。

## 背景、目标和非目标

A已识别同版本不同内容，B已有锁、隔离修订、state最后发布及第三方冲突保留，C已有模型实读/意见闭环。当前0.6仍接受schema5、随附模块与作品手册分置；直接拷CLI既可能漏模块，也会覆盖定制或让旧进程继续写。

目标：从作者指定的本地可信来源，生成只读完整计划，显式更新完整轻量包，保留定制、备份和恢复依据；新入口在独立目录可用。复用B的文件写入/事务发布/冲突保留/遗留锁恢复。没有常驻服务、数据库、新依赖或完整质量引擎的重复副本，不自动理解自然语言授权、更新schema或合并代码定制。

## 兼容与权威

0.7新作品默认schema6。`state.tool_control`记录generation、安装内容身份、不可变事件及幂等结果，仍以state为业务权威。旧0.6实际解析器须拒绝6；不能仅加一个会被旧工具忽略的generation sidecar。新版继续读取1–5。

旧作品先只读plan，确认来源完整与备份条件，再由新主项目入口显式`tool enable`将5提升6，保存原始state及启用后精确哈希；1–4先按原流程启用到5。启用不更新工具、不改事实。只在generation=0、当前state仍精确等于启用后字节且没有后续业务写入时，允许另一次明确授权的`tool undo-enable`恢复原5；不会在工具回滚中暗做schema回退。

成功工具更新仅将业务revision和generation各加1，保留snapshot、units、journal及旧来源绑定。原治理任务与作者范围不因更新扩大。更新需plan权限、当前revision、稳定operation_id、作者原话和计划指纹。任何活跃修订、修订分支或未完成事务均拒绝更新。

## 包与本地定制

新版轻量包在`.writer/tool/`内自带运行模块、必要手册、来源/许可和原版技能，使用schema2构建清单及tool-root资源范围。只复制声明文件，不复制引擎、作品、Git和验收资料。main/workspace-copy公共资源身份可比较，来源commit/dirty单列；磁盘指纹不是执行签名。

作品根的AGENTS、技能和文档默认保留，列出与原版的差异。可显式选择更新未定制的受管手册；缺失可新增，有可信旧清单且字节未改可替换；未知或已定制文档拒绝覆盖。工具目录内未知文件、已认证运行模块被改或清单损坏先报冲突。无清单的旧副本不能假称未定制，必须另行明确接受精确观察到的旧工具基线并保留完整备份，才允许替换；此确认不许可覆盖作品根定制。

## 接口

|命令|语义|
|---|---|
|tool identify / compare|保留现有只读身份与差异检查|
|tool update-plan|本地来源、目标基线、完整包/字节数、文档保留/冲突、schema前置条件及计划SHA；不建备份、不执行来源代码|
|tool enable / undo-enable|显式协议保护及严格限定的无后续写入回退；完整原话与原字节|
|tool update|在目标目录之外运行；重新核计划/CAS/源与目标，创建备份并发布完整工具|
|tool list / recover|列更新事务；明确complete/rollback，未完成事务阻断普通入口；无自动清理|

工具输入由Codex准备，作者说明来源、需要保留的定制与允许更新范围。不会让普通作者手工找UUID或填写JSON。计划含预填request和阻断原因；不以“确认”重复询问已授权的工具维护或隔离验收。

## 状态机、时序与复用

只读plan → 固定旧/新备份 → prepared → applying → completed；故障保留pending，恢复到completed或rolled-back；第三方变化进入conflicted并保留三方。成功后撤销只能新操作，不逆转旧终态。

复用`.writer/transactions`及B文件发布器，工具事务使用明确kind和新事务schema。旧0.6也能看见prepared/applying并阻断普通命令，不能误恢复工具事务。新工具区分恢复命令。每个目标都在受管工具/显式手册/不可变更新事件/state白名单内；路径拒绝穿越、链接、特殊文件和硬链接。

更新器先在同盘独立区准备完整包及代表性验证作品，用新入口执行help、doctor、status、discussion context；验证作品从B的明确业务清单复制，不含分支/事务历史。实际目标安装后核新工具字节并执行help，最后发布state与generation、结束事务。普通目标读写在pending期间保持阻断；不能为了验证开一个可写旁路。正式完成后由调用者再从实际副本入口跑doctor/status/context，作为整合验收。

发布复用原子文件写、fsync、逐文件旧/新比对、state最后切换和第三方现场保留。更新只能从被替换工具目录之外执行；源和目标不能互为嵌套。没有物理断电或共享盘持久性保证。

## 进程代次与异常

所有写入口（含原coordination入口）检查已加载runtime与已观察到的作品generation；嵌入入口启动时捕获本作品generation，主入口首次读作品时捕获。代次变更后旧进程拒绝继续；没有读过目标的主进程不伪称已经使用过其旧代次。schema6进一步阻断旧0.6业务写。

来源变化、目标变化、模块缺失、清单错误、未知定制、过期revision/plan、活动修订一律在发布前拒绝。恢复遇不属于旧/新字节的目标，不覆盖，保留旧/新/外部和报告。遗留锁沿用B的哈希、原进程存活核查及明确作者恢复依据，不因超时抢占。幂等操作相同ID和相同输入返回历史结果，不重复revision/generation；异输入同ID拒绝。

## 回滚、迁移及风险

取消plan无写入；发布中故障按原事务回滚或补完。回滚恢复工具旧字节和原state；若原state已是6而旧工具不支持，使用外部新入口重试，或在严格无后续写入条件下另行undo-enable。不会复制旧schema数字去掉新数据。成功更新后保留备份；不自动删除任何历史。

主要风险是混合构建、定制误覆盖、旧进程继续写、遗漏来源许可、验证目录与实际入口不一致。对应完整白名单清单、根目录默认保留、共享pending屏障/schema6/generation、源许可完整性、独立包与实际副本双重运行。恢复权限和同用户文件访问不是强身份隔离，任意编辑器锁外瞬时竞态仍有明确边界。

## 分阶段实施与测试

先收敛schema/包资源和统一代次门禁，再复用文件事务实现更新/恢复，最后补技能和手册。最终源码运行npm test、doctor、smoke；未改引擎不借用其结果。真实CLI覆盖T24–27及A/B/C回归、Unicode/空格、无清单旧工具、定制、损坏、嵌套、逐发布断点/ENOSPC、真实在途进程同步屏障、重复操作、三方冲突。

以多个实际Codex进程创建六章、从文件恢复、未来来源与旧章修订/意见链，再升级完整工具并实际从新副本操作；另用百章必要文件副本核全部原文/事实/引文和真实尾段阅读。完整源码、输入、stdout/stderr/exit、失败尝试、哈希和封存清单留存。Windows本地、模型实读、故障注入各自有界，不能说成Linux/NFS、真人或物理断电验收。
