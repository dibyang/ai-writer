## 去 AI 味的适配

专门读取并留存用户指定的上游专题，固定提交为 `6d72f70e5fe3de110b457fd6bc81ede6ea614702`。原文、MIT 许可及 SHA-256 见 `docs/usability-sources.json`；旧来源快照不覆盖。

流程为：明确作者声音和版本 → 扫描候选并完整实读 → 分类诊断 → 保存原字节 → 已登记稿正式回退 → 定点修改 → 连读与前后事实/情绪/知情边界对照 → 重新登记 → 带哈希报告及草稿导出。只要求审查时先报告，明确授权润色时直接修改。

只读 style-scan 不给 AI 概率，不把命中当错误。小说保护人物知情、线索和物件交接；剧本保护可表演行动与对白目的；历史散文保护引文、数字、证据和推断边界。未移植禁词密度评级、固定删字比例或统一句式禁令。

## 真实 Codex 流程

使用本机 `codex-cli 0.162.0-alpha.17.2`、Node v24.15.0、Windows，从主项目 cwd 执行 `codex exec --json --sandbox workspace-write`，模型沿用用户当前设置。每段保留 request、events、stderr、最终消息、process-result 和实际作品，不以 exit=0 代替产物核对。

- [novel-a](novel-a/result.md)：533 秒，25 个命令执行事件。创建长篇、冻结两章、登记第一章，保留第二章待登记，实测导出只含第一章且报告排除稿。
- [novel-b](novel-b/result.md)：899 秒，75 个命令执行事件，其中 57 次产品 CLI。仅按文件恢复，正式重定位原文件、登记第二章、续写第三章、完整三章去味、正式回退重登和滚动审查；最终 revision 12、三章、无来源漂移或未登记正文。
- 小说实际修改九处，保留有作用的“不是黑袋，而是蓝袋”、五针白线、手指结痂、饭盒标记及父亲/经手人尚未知信息。第三章扫描零命中仍经完整实读并修订重复视线描述。原文、前后哈希与保留理由见报告。
- novel-b 结束后才同步最终目录重命名修复，旧工具副本和 state 前后哈希保存在 `tool-refresh-v3/`。主会话用最终随附工具再次实际导出到 `final-runtime/novel-export/`，合并稿 SHA-256 与 novel-b 一致：`d71b8d93dfeab356815c069fe2bb1645e06ec944f2837d65163a9caddee478cc`。
- [genres](genres/result.md)：878 秒，53 个命令执行事件，另有 62 次产品 CLI 调用日志。剧本和历史散文均完成原稿登记、正式回退、去味修改、全文复核、重新登记及导出，均 revision 3。剧本 7 段对白逐字保留，道具数量、时间与借用手续未变；历史两处引文、数值、完整证据限定段保留。主会话另作 [全文复核](manual-verification.md)。
- genres 发现独立作品缺少来源/许可，主会话修复后同步三个作品，正文和 state 哈希未变。旧结果保留“未修”当时状态，后续修复记录见 [缺陷处理](defects.md)，不能用旧报告代替最终结果。该阶段记录的三个范围外验收文件变化来自主会话整理证据，产品和输入未被该子进程修改。
- [final-recheck](final-recheck/result.md)：201 秒，实际 19 条 CLI 命令、53 项核对通过。用 v4 主工具创建空作品，再用随附工具创建第二个空作品；两级均携带许可、来源清单和原文，实际重算哈希一致。三文体重新检查并导出，正文、state、旧导出未变，新导出与对应旧导出 SHA-256 相同。
