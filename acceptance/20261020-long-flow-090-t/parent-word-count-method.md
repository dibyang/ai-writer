# 字数与读取指纹的口径

篇幅门槛和最终汇总采用**正文Han**：先去掉`^#.*$`的章题行，再计Unicode Script=Han字符；数字、标点、英文不计。flow及chapter-*-metrics.json使用此口径，最终final-support-verification.json会重新从当前30正文独立计算，不以自报达到门槛。

父在r75当前稿实算：总141346正文Han；新增19—30章72208。19为10566、25为10627，其余10新章5039—5254。旧1—18当前共69138，S继承时69112；这26字差来自本轮R1旧章受控修改，不应把`141346-69112`全部算成新增12章篇幅。

F的final-read-before.json由f-entry.mjs实际生成，其中chapters[].han直接计整份文件，**包含章题**；它是读前指纹辅助字段，不是本轮正文门槛数据。读前后实际SHA/字节/路径/行数用于确认当前版本，F原捕获保留，不改成另一计数方法以制造表面一致。章节统计或F报告若引用这列，应按其实际全文口径理解；最终门槛、总字数和新增字数以明确排除章题的父支持核验为准。没有以标题凑5000/10500门槛。

FastCtx会显示末尾空行；各JSON的lines有的去掉虚拟末空行，所以与工具EOF行数可差1。严格native读取证明按当前真实每行与实际返回文字匹配，不能只靠自报行范围或字数认定读完。
