# 本轮发现、修复和验证边界

本文件记录开发中真实失败，不删除失败输入，不把早期失败运行改写为通过。最终源码以 `sources/candidate-v2` 为准；初次原生六章创作使用 V1，随后原生修订、复核和百章回放使用 V2。V1 已完成创作不等于 V2 重新创作六章。

## 产品问题

| 问题 | 原失败证据 | 修复后的证据 |
| --- | --- | --- |
| 新 review 路由接线时没有暴露共用 review 方法，导致登记失败 | `commands/feature-first`、`commands/first-regression` | 补齐共享出口，之后功能用例和最终 132 项通过 |
| 独立修订分支可借较宽讨论授权处置声明范围外意见 | `commands/scope-preview-before` | 变更意见前独立检查意见锚定章节与会话范围；`review-scope.test.mjs` 第1项 |
| 扩展连读报告可附带新增范围外意见 | `commands/scope-preview-before` | 报告阅读范围可以较宽，新增意见仍须在修订范围；第2项 |
| 空摘要预览先报缺项，未提示暂停授权，容易诱导继续补写 | `commands/scope-preview-before` | 预览先呈现授权阻断，再列登记缺项；第3项 |
| 结构化审查文件落盘但 state 发布失败，孤儿仍计有效覆盖 | `commands/scope-orphan-before`、`commands/orphan-cli-before-run` | state 索引是发布权威；孤儿列 `unpublished_records`，不计覆盖。真实 CLI 注入 ENOSPC 后状态不变，重试只正式发布一次；第4项和 `orphan-cli-after-run` |
| 代理先同名重记作者保留，之后可借一般润色授权翻转选择 | `commands/author-recheck-before` | `author_choice` 持续保留；改变选择须新作者依据，落实原已采用项不用重复确认；第5项 |
| 真实修复后其他正文或依赖再次变动，旧 application 会阻止当前新稿复核 | `commands/author-recheck-before` | 保留原真实修复提交，允许绑定当前有效实读报告重新 verify，不捏造第二次正文修复；第6项 |

上述六项边界回归在 `commands/boundary-after` 通过，最终完整回归在 `commands/candidate-v2-regression` 通过。异步发布、全局 CAS、原来源版本及日志保护另有完整实际 CLI 矩阵，不用单元测试代替进程间验证。

## 测试与辅助材料问题

- 默认新作品改为 schema5 后，旧回归中默认 schema4 的断言需要更新；明确测试旧保护启用目标仍保持4。这是新协议兼容约束，不通过修改旧作品消除差异。
- 中间一项断言错误地要求改稿后的证据 SHA 不变，改为分别核对事实语义与正文新版本锚点。第五章只删一字仍须更新该章全部证据的正文 SHA，不能伪造原 SHA 保持测试“绿灯”。
- 初始化复用了 B 的辅助脚本，`fixtures/tool-0.4` 名称沿用旧名，但生成的只是本轮 HEAD 的9份0.5模块子集，该目录未被用于兼容结论。有效旧工具对照是完整11份 `fixtures/tool-0.5`，有源提交与逐文件 SHA。
- 补丁上下文不符时工具拒绝写入，调整上下文后再应用；提早读取未完成记录器输出曾报 ENOENT，待进程完成后读取。未覆盖失败日志，未据此手工改 state。
- 首轮原生辅助脚本一度把预期拒绝退出码写成1，实际产品退出2；新标签保留正确断言，原失败也保留。此类辅助预期错误不冒充产品拒绝失败。
- 第三轮辅助核对把 journal 的 patch 结构误读成顶层 changes；在产品 preview/record 前停止，错误原输出及修正报告留存。运行中 events.jsonl 仍追加，首次静态清单不能固定它的最终 SHA；该轮改为封存静态材料、另留观测前缀，由父流程在进程结束后封存完整日志。
- 第四轮辅助初始化多传了 init 不接受的 --project，CLI 在建目录前拒绝；改用 --path，原调用保留。它未改变百章副本。
- 第四轮独立断言误以为幂等commit回复一定含revision，随后改核unchanged及捕获的前后state同SHA；未重试或修改真实事务。该辅助断言失败保留，不算产品幂等失败。
- 父流程首次只读字数统计将正则转义两次，编译失败、没有写文件；改为独立 UTF-8 脚本，结果绑定原始冻结正文，见 parent-audit/fresh-reading-observation.json。
- 父预审首次过严地要求所有“正文暂停”都必须是 stage=paused，实际新短篇和百章处于 structure，任务写明暂停，授权仅 discuss/plan、两个正文范围为 null。这同样是允许讨论规划、禁止继续正文的合法状态；改为分别断言阶段、任务和权限，而非修改作品元数据迁就验收脚本。原失败 parent-preflight 和通过的 parent-preflight-fixed 均留存；最终报告列真实阶段。

## 不扩大结论

- 跨章目标、选择、后果、关系变化必须实际读稿，脚本仅校验结构、引文、版本和覆盖。功能表齐全、模型说 resolved、review 记录有效都不是文学通过、作者定稿、真人盲读或市场验证。
- 百章测试使用原封存作品的独立副本，正文100章保持原字节；本轮实际文学连读范围为95–100，1–94只作完整性与必要来源回查。旧 stale/uncovered 审查如实保留。
- 登记减负恢复原摘要和原增量，不推断新情节，不自动确认六项语义检查；旧模板本来就填路径和哈希，旧增量账本也继续复用。
- 耗时仅本机进程观察，不能换算作者节省分钟数；对比同时区分新旧协议。故障注入是进程退出及 ENOSPC 模拟，不等于物理磁盘写满、断电或其他操作系统验收。
- 本轮未改内置引擎，无新运行依赖，不声称执行 `test:engine`。未实现 D 批工具安全更新，不自动迁移、更新或修订现有作品。
