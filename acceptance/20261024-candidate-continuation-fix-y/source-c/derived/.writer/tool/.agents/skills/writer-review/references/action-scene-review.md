# 动作与场景描写审稿规则

Apply this module when the user asks about 动作描写、打斗、追逐、救援、走位、场景描写、空间感、环境描写、场景切换, or when a decisive outcome depends on who moves, sees, reaches, blocks, or acts first. Apply `general-review.md` first. For wounds, clues, object handling, extraction, or evidence reveals, also use `physical-logic-operability.md`; that module checks whether an action can happen, while this one checks whether readers can follow and feel it.

## 核心判断

读者不必看见每一步，却应能复述关键行动：人物原本在哪里、想做什么、被什么挡住、怎样改变做法、付出什么代价、行动后人和物到了哪里。安静的对话、等待、查账和照料也可以是完整场景；不要强加打斗、镜头术语或每段固定的感官清单。

## 审稿顺序

1. **定住场景。** 检查时间、地点、在场者、视角人物及当前目标是否足够清楚。转场后若人员、时刻或任务改变，读者应能在关键行动前重新定位。同场对话或停顿期间若有人进出、靠近、退开或交接物件，后续动作也须承接新位置和持物状态。只标出影响理解的方位，不要求画完整平面图。
2. **还原关键动作链。** 对改变结果的关键几步，按“起点或持物状态 → 阻力或触发 → 动作 → 可见结果”复述。检查谁持有物件、用哪只手、从哪里到哪里，以及旧伤、速度、距离、门宽、光线和阻挡是否影响选择。可跳过不改变结果的走路、抬手和交接。
3. **核视角与信息到达。** 人物只能依据当时能看见、听见、摸到或已被告知的事行动。若关键动作发生在视线外，正文须给出足以支持反应的声响、传话、痕迹或下一次观察；不要让叙述提前替有限视角人物知道结果。
4. **让场景参与事件。** 关键环境细节应承担一种具体作用：改变路线、遮挡视线、增加时间或体力成本、暴露线索、限制接近、触发记忆或改变人物关系。纯氛围描写可以保留，但不应挤掉读者理解行动所需的一个关键地标或阻碍。
5. **调节叙述速度。** 危险、误判、反转和不可逆选择可放慢到读者能跟上；重复劳动与无争议的移动可压缩。避免每招逐帧罗列，也避免用“几人一番争斗后获胜”跳过决定胜负的动作。动作之后检查伤、位置、物件归属、情绪和下一步选择是否留下余波。
6. **用人物习惯筛细节。** 守门者先看退路，伤者先护痛处，熟人先注意彼此异常；这些是可能的角色化选择，不是固定模板。动作应显出此人的训练、恐惧、欲望或关系，而非所有人都按作者最有效率的步骤行动。

## 何时判问题

- **硬问题：** 决定结果的人或物突然换位、越过已写明的阻挡；受限视角提前知道场外事实；关键动作被省掉后只剩结果，读者无法解释胜负、伤害、救援或证物显露；环境描述与随后行动互相冲突。指出文本中可定位的前后两处证据，并说明读者会误看见什么。
- **需优化：** 动作可能成立，但缺一个简短地标、触发或结果，导致读者回读；场景细节很多却不参与事件；连续长段技术步骤掩住人物压力。优先提出一处最小修改，例如补一个开度、站位、传话来源或伤后的反应。
- **风格偏好：** 只是想写得更“电影感”、更快或更华丽，而现有文字已清楚且符合叙述视角。不要把偏好当硬伤，也不要要求所有动作都逐步展开。

## 与其他模块的边界

`physical-logic-operability.md` 核物理和程序能否成立，`natural-language-authenticity.md` 核动作词、句子和对白是否自然，`psychology-readability.md` 核高压时身体与心理反应。本模块把这些放回连续场景，检查读者能否看清行动和感到压力。若一个问题同时落在多个模块，只报一次，说明它主要阻断了什么。

## 输出要求

用于审稿时，简要给出动作因果、空间方位、环境作用、视角信息和节奏的结论；只列会改变读者理解或场面力度的具体问题。每条问题引用可搜索的原句，说明前后位置或状态，并给出最小修正方向。用户只要求审查时遵守 `SKILL.md` 的审查边界，不直接改正文。
