# 独立候选第七章登记修复验证

本轮按作者经小说会话转交的限定授权，暂停百章扩容。只修复“独立修订候选固定 1–6 章，已有第七章封存稿无法登记”的工具缺口。真实主稿、原候选、会话、令牌、来源、封存稿及随附工具均不修改；不写第八章、不合并主稿、不提交或推送。

## 验证方式

- 新单测 `tests/candidate-continuation.test.mjs`：派生完整消费链、显式采纳、原样前缀、单章范围、错误令牌、作者证据、state/session CAS、清单来源、私有附件、目标重复、并发锁、正文/凭据篡改、发布拒绝。
- `run.mjs`：只读复制真实作品所用旧工具包的清单归属文件，逐项验哈希，形成独立兼容夹具。没有复制真实小说正文、状态、会话或令牌。旧包初始构建 `9e26ebbf6120c9b49d31bfeee56099da843618010e0451ee658c8adacb7f532c`；来源信息见 `legacy-source.json`。
- 旧包真实 CLI 初始化独立短篇夹具，登记六章；创建修订区，rewind 后完整重新登记六章；保留旧候选和主稿，再用新工具派生下一章采纳候选。每条命令在独立进程执行，JSON 输入、stdout、stderr 和退出码均保留。
- Codex 实读独立样稿，核对回执归属、候选修改的日期和“明日只是约定”的事实边界。篇幅短，仅证明兼容操作与事实登记，不冒充百章压力验证、真实小说登记、真人盲读或文学验收。
- 全量 `npm test`、`npm run doctor`；最终固定制品还须解压并复验。未改内置引擎，不将本批称为引擎变更。
- `observe-real.mjs` 只读保存真实现场 33 来源及 6 个固定文件的哈希。备份完整性仍由原小说会话负责，此处未审计其全部备份。
