# 去 AI 味：诊断、修订与复核

这项流程由 writer-review 执行，小说写作自检也使用其中的判断原则。目标是改善读感并保留作者声音。它不承诺外部 AI 检测器分数，也不会为了“像人写”故意加错字、乱标点或编造细节。

## 怎么开始

仅诊断：

> 对作品的第 1—3 章做去 AI 味专项审查，只报告。完整阅读正文，定位成片模板表达、情绪空转、对白趋同、节奏单调、收尾重复和解释过满。每项给原句、影响与最小修改方向，同时列出应该保留的声音资产。

授权修改：

> 按作者现有文风，对第 1—3 章去 AI 味并直接润色。保留人物、情节、数字、事实、信息边界和有效修辞。先备份原文，处理已登记章节的回退，定点修改后连读复核，重新登记，并给实际改前改后对照。

已经授权润色时，Codex 可以执行相应修改，不需要再次索取同一授权。只说“检查有没有 AI 味”时，先交诊断。

## 完整流程

1. **确定版本和边界。** 确认文体、目录、范围、作者声音与修改授权；记录原稿哈希、追踪修订号和应保留的表达。
2. **扫描加实读。** 可用 style-scan 定位候选，然后完整阅读。扫描没有命中的对白、心理和节奏问题也要判断；命中词句不能自动判错。
3. **按阅读代价分层。** 区分局部高置信问题、连续模板风险、主观风格偏好和待核项。修改范围由实际影响决定，不按词频给全篇定级。
4. **保存原文并定点修改。** 先保存对应原稿和哈希；已登记文本通过正常回退流程处理。减少重复与空转，恢复人物具体反应和自然语气；保留必要因果、伏笔、情绪承接和成立的修辞。
5. **连读复核。** 核对改前改后的事实、人物所知、动作空间、情绪结果及相邻章节承接。没有问题的地方保留；扫描命中可以有充分理由地保留，不要求清零。
6. **重新登记和交付。** 按实际最终正文重新登记受影响单元，检查未登记稿、旧报告失效和导出排除清单。报告绑定前后哈希，并列出实际改动、保留理由及未覆盖项。

## 按文体判断

| 文体 | 重点 | 必须保留的边界 |
| --- | --- | --- |
| 小说 | 人物口气、情绪的诱因与后果、重复解释、跨章收尾和节奏 | 不改剧情、角色知情、伏笔公平和物证状态；不把所有句子改短 |
| 剧本 | 可表演行动、对白目的、角色差异与潜台词 | 不强加小说心理描写，不凭文字篇幅裁定实际表演时长 |
| 历史散文 | 史料转述是否自然、解释是否重复、叙述者声音 | 不补无来源的心理、对白或感官现场；证据限定词可能不可删 |
| 散文/非虚构 | 观察是否具体、论述和回望是否有内容、个人声音 | 不虚构经历；允许舒展长句、留白、议论和有作用的回环 |

## 只读扫描命令

从主项目执行：

```powershell
node bin/ai-writer.mjs style-scan --project "works/雨夜来信" --draft "正文/0001-来信.md" --out "审查/语言线索-r1.json"
```

独立作品把命令前缀换成 `node .writer/tool/bin/ai-writer.mjs`；在作品目录可以省略 `--project`。

输入可以是尚未登记的正文。输出含原稿哈希、位置、上下文和待复核理由；`ok` 只表示扫描执行成功。Markdown 引文块和代码块不参与机械扫描，仍须按任务实读。扫描范围有限，人物声音和情绪因果等需要 Codex 判断。指定的输出文件必须是新的 `审查/*.json`，不会覆盖旧报告。

## 交付长什么样

简明报告至少说明：

- 阅读范围、文体、原稿/修订稿哈希，以及审查性质。
- 问题位置、原句、实际阅读代价、处理结果。
- 实际改前改后对照；没有改的地方说明保留理由，不虚构改动。
- 人物声音与事实等保护项的复核结果，以及尚待作者判断的风格偏好。
- 追踪是否重新登记、哪些后续单元已复核、哪些未覆盖。

可用的详细执行规则随作品保存在 [去味审修参考](../.agents/skills/writer-review/references/deslop.md)。
