# 长篇创作状态与恢复设计

状态：本地实现与实跑候选；2026-10-15。参考固定提交 `6d72f70e5fe3de110b457fd6bc81ede6ea614702`，具体取舍见 reference-audit.md。

## 背景和目标

原状态每章同时保存完整 before/after，时间线增长时累计空间接近平方增长。续写又注入完整状态，角色和旧线索多时容易超预算。分卷计划、已发生事实、人物所知和审查覆盖尚无明确接口。

本轮让长篇能分卷规划、从文件恢复、按线索召回、导入自有旧稿，并安全修订和回退。保留小说、剧本、历史散文和散文的现有入口与草稿边界。计划不自动变成事实；程序核对哈希、引用和结构，语义由 Codex 阅读判断。

## 数据和接口

- `long-enable --expected-revision N`：锁内备份旧状态并迁移 schema 1→2。修订号增加，旧书仍能不迁移继续使用。新书也显式启用，不暗改既有状态。
- schema 2 的 state 保留当前快照与线性章节索引；每章可逆差量写入 `.writer/journal/`，state 最后原子替换。数组追加使用 append/truncate，映射只记录变化键。不可达的中断文件保留，不自动清理。
- `volume --input` 保存范围互斥的分卷契约；`outline --unit N` 返回当前卷契约、当前剧情单元和章纲。已消费卷纲修改会触发来源失效，须 rewind 后重核。
- 长篇登记用 `changes` 合并当前快照，避免整份抄写。characters 是当前角色短状态；threads/timeline 仍兼容旧格式。`ledger` 保存带稳定 ID 的事实、伏笔、物证和关系条目：角色关联、状态、到期章、作者事实/读者已知/人物已知、正文证据。更新须交证据，既有观察不可改写；新信息用新条目补充。
- `context` 必带全书规则、当前卷/剧情单元、出场角色、显式 recall_ids、到期未结条目及近三章。其余 ledger 按角色和近期变化召回，并公开遗漏 ID；预算不够则拒绝，不悄悄丢强制信息。
- `recall --query` 按 ID/正文摘要/角色/标签检索已登记材料，返回正文路径、哈希和匹配项；检索是定位，不等于已读正文。
- `review --input` 登记实际阅读范围、报告和正文哈希；`check` 显示滚动窗口欠审/失效情况。每三章建议读当前三章与前三章；不把模型自检升级为真人盲读。
- `import-index --input` 索引作者提供的 UTF-8 分章文件清单，保存源文件副本、哈希与明确顺序；`import-next` 顺序复制下一章到正文。每章仍经章纲、Codex 阅读、真实摘要及追踪登记。没有登记前不跳到下一章，不伪造全文分析。

## 状态、故障与回退

所有作品内写操作使用同一锁和修订号。迁移/回退先写完整备份，差量文件使用随机 ID 且不覆盖，最终 state 是提交点。失败前不推进；重复相同登记按指纹幂等。回退逆序应用差量并保留正文和冷记录。journal 丢失/哈希不符时拒绝恢复，不猜状态。所有输入沿用相对路径、符号链接和大小保护。

旧格式只由原路径读写；迁移是显式工具操作。独立作品复制新增 lib 文件，离开主工作区仍可续写。旧验收目录与其工具版本保留，避免新工具覆盖旧证据。

## 验证与边界

针对差量往返、迁移、断点/损坏、预算、遗漏、到期、信息隔离、不可变观察、来源漂移、导入顺序和审查失效做行为测试；跑 npm test / doctor，未改引擎时沿用其版本并跑回归确认。再由两个顺序 Codex 会话完成跨卷创作与文件恢复，分别记录输入、命令事件、退出码、正文及导出哈希。小说语义实跑与合成容量测量分开报告；不宣称百万字/真人/市场验收。

## 本轮不扩展

不引入平台爬虫、Cookie 提取、浏览器进程管理、全局作者记忆、自动付费封面、多宿主安装或强制网文比例。已有插件可在作者明确提出这些任务时使用。外部对标只迁移有证据的方法与失效条件，自有旧稿保持续写基线身份。
