# ai-writer 首版设计与实现边界

状态：0.1.0 本地候选，2026-10-15。

## 背景与目标

现有 story-gate-studio 侧重小说质量门禁，剧本主要覆盖短剧试制；历史散文经验分散在另一个作品。参考项目提供较完整的网文创作方法，但其宿主脚本和规则不能直接代替我们的文体差异与声音保护。

目标是用同一个 Codex 工作区创建四类作品，以本地文件恢复长篇创作，保留文学判断与确定性检查的界限，并能够单独携带作品目录。

## 非目标

首版不实现独立模型服务、网页编辑器、自动发布、平台爬虫、图像/视频生成、自动旧稿迁移或自动文学评分。没有调用付费 API，也不修改用户全局 Codex 配置。

## 现有与新增流程

story-gate-studio 使用原私有发布清单生成快照，保持原代码和许可。ai-writer 新增 7 个 skills、4 种文体路由和 Node 文件管理工具。参考仓库仅保留所读规则的原文与许可快照；其 hooks、Python 工具不进入运行链。

## 核心约束

作品与工具分开；四文体标准分开；素材不是指令。原作品只读分析，示例另写。主版本不依赖第三方包，Node >=20。文件用 UTF-8；作品引用限制在目录内，不允许路径穿越或链接。状态不记录凭据，不上传正文。

## 接口与数据

命令及字段见 workflow.md。配置 `writer.json={schema_version,title,kind,language}`。细纲保存 `unit,title,goal,change,beats,cast,setting_refs,research_refs,forbidden`。

唯一状态 `.writer/state.json` 保存版本号、revision、完整 snapshot 与顺序 units。每个 unit 含正文路径与哈希、摘要、前后快照、来源哈希与指纹。snapshot 内 characters 为当前角色状态，threads 为未兑现项，timeline 为事实时间线。大纲不写入已发生状态。

历史事实卡保存 status 与 claims；每条 claim 含类型、陈述、边界、source_dependency 和带定位/原文/核验日期的 sources。verified 是核验声明；程序不判断语义、独立史源或事实真假。

## 状态与时序

空作品 → 有细纲 → context → Codex 草稿与自检 → draft-recorded → 下一单元。正文被改时追踪失效；rewind 从最早受影响单元回到之前快照，再按顺序重新登记。工具不定义自动“正式稿/作者通过”转移。

context 带配置、细纲、设定、研究、状态和上章的源哈希。record-template 在动笔前预填这些证据和当前完整快照，留空摘要必须由 Codex 据正文填写。record 持锁后重读状态，校验修订号、顺序与全部来源，再一次原子替换状态。单文件权威避免多追踪表半更新；各阅读视图随取随生，不做第二份权威。

已登记单元的正文和消费过的来源持续校验；status.changed_sources 定位资料变更，check 报错，context/export 阻断。状态文件本身在登记中必然前进，其历史输入哈希不参与持续漂移判断。导出清单保留修订号及每个单元的来源哈希。

## 异常与幂等

锁文件用独占创建，存在则拒绝；中断后不按超时自动抢锁。JSON、编码、引用、预算或来源校验失败时保持旧状态。状态写入先同目录临时文件，再 rename；这是文件级原子替换，不保证断电持久性。作品应使用本地备份或版本控制。

同一登记指纹重放为 no-op；旧 context 在新来源下拒绝。init 与 export 只接受新目录，先构建临时目录再重命名；失败清理本次临时目录。不会覆盖历史交付。

## 回滚策略

rewind 先保存完整旧状态备份，再退役后续登记，保留全部正文。自动恢复旧快照文件为当前状态未提供；操作者核对后可根据备份重建，不能假定备份恢复即内容一致。工具版本回退通过替换项目代码；作品快照工具随作品固定，不自动升级。

## 兼容与迁移

schema_version=1，不支持的版本明确报错。Windows 本次实测；Linux/其他 Node 版本由 CI 配置表达覆盖意图，未运行前不宣称通过。已有作品先保留原稿，另建工作区后按授权导入；首版不提供静默目录改写。

## 测试与风险

覆盖四文体文件全流程、哈希漂移、并发锁、幂等、回退、路径、编码、历史缺证、预算和独立作品工具。内置引擎另跑原有测试。文学实读、史实核验、新 Codex 会话发现、长篇跨章语义连续性和真人体验不由这些测试证明。

语义依赖可能超出显式引用：规则改变后由 Codex 分析受影响的已写范围。正文和单个引用文件保持 1 MiB 上限，内部完整快照追踪使用独立的 64 MiB 上限，写前检查容量以免生成工具自己无法恢复的状态。过长全书状态仍需后续分片设计，context 预算超限会停止，不能偷偷删掉角色或线索。共享盘/NFS 原子与锁语义未验，不建议凭本地证据宣称支持多人协作。

## 分阶段交付

1. 已实现：四文体 skills、来源映射、作品管理与质量引擎快照。
2. 本次验收：本地工具与原引擎回归、独立目录交付、来源哈希核对；真实Codex三文体样稿全流程、剧本来源更正后回退重登、100单元合成状态容量。
3. 后续按实际任务：essay真实创作试用、作者阅读验收、数百章语义连续性及分层召回；新会话技能发现已由discovery-native实测，不能据此替代创作质量。
4. 对外分发前：确定自有规则许可、插件许可与公开范围；不把当前内部候选直接当作公开发行版。
