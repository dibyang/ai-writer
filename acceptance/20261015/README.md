# 三文体真实 Codex 创作验收

日期：2026-10-15。性质：本地候选验证。真实 Codex 创作及知情自检，不是模拟模型输出、真人盲读、排演或作者定稿。

## 实跑安排

小说、剧本按顺序启动独立的 `codex exec` 会话，使用当前登录与默认模型，不指定替代模型，不改全局配置；保留请求、JSONL事件、最终答复、进程退出码和耗时。历史散文由当前Codex主会话实际创作与实读，通过同一CLI逐步执行，保留每次命令输入输出；没有伪造第三个独立进程或模型事件。三者均从初始化、创作资料、细纲、context开始，实际写作、逐单元登记、自检、审查和导出。

## 已确认问题与修复

| 问题 | 修复 | 可审计证据 |
| --- | --- | --- |
| 登记后的研究资料变了，旧版仍允许继续或导出 | 持续核对已消费来源，status 定位，check 报错，context/export 阻断，按最早消费者回退重登；导出清单带修订号和来源哈希 | `source-drift-repro.json` 记录旧版允许、新版阻断的同夹具对照 |
| 完整快照累积后超过1 MiB，工具生成的状态自己读不回 | 内部状态独立64 MiB限制，单篇正文和引用保持1 MiB；超限在替换前拒绝 | `state-capacity-repro.json`：3647072字节同文件旧版失败、新版恢复；100单元回归文件1701095字节并生成第101单元context |
| 登记时手工拼哈希和完整快照容易出错 | 新增写前 `record-template`，预填真实证据和完整快照，摘要留空，写后据原文填写 | 模板、过期来源、空摘要回归；剧本/历史实跑使用 |
| 历史卡对史源传承的要求只写在说明里 | `source_dependency` 成为必填，保持“字段不证明史实”的边界 | 历史卡缺项回归；真实历史样稿另验 |
| 合法HTTPS史源链接被路径检查误报 | 路径识别排除协议末尾的s:/，保留实际盘符提示；不删除史源链接 | history-live/07-command.json保留原警告，09-command.json同稿修复后无发现；HTTPS及正反斜杠盘符回归 |
| 常规自检报告过重，完整稿任务容易加载发布评分规则 | 审查按任务路由，常规自检保留覆盖、必要问题、声音资产及限制；需要逐段台账时才展开 | writer-review 本轮更新，实际读过的小说报告保留，不伪称重新创作 |

`novel-create/initial-bundle/` 保存小说初始化时的旧工具与两个变动技能，供前后对照。三份样稿携带工具已显式更新为本轮最终候选；正文、设定和追踪没有因此改写。15份文件的前后哈希见final-tool-sync.json，变动前副本在final-tool-sync/。独立作品默认固定携带版本，本项目没有实现自动升级命令。

- 系统 npm Codex CLI 0.124.0：首次在受限网络执行中返回 socket 10013，未写正文；网络执行上下文允许后，又因当前 features 配置格式不兼容退出。
- 桌面版自带 CLI 0.162.0-alpha.17.2：最初拒绝已移除的 `--full-auto` 参数，按其本机帮助改用 `--sandbox workspace-write`，随后小说运行成功。未修改用户全局配置或关闭沙箱。
- 前三次失败原始日志分别在 `novel-create/`、`novel-retry/`、`novel-native/`，不计为通过。失败调用无创作命令，不能算完成创作。
- Windows 的 `python` 别名不可运行；技能格式校验改用 Workspace 内置 Python，并显式 `-X utf8`。只更换本轮调用入口，没有修改全局 Python。
